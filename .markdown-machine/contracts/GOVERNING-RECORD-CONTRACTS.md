# MM-GOVERNING-RECORDS/1

This registry defines positive records and operation floors. Records are
validated with `MM-RECORD-GRAMMAR/1`; recovery-only records are defined in
`MM-RECOVERY/1`. Lists marked by an id or pair key are sets and duplicate keys
are invalid. All omitted or unknown fields fail closed.

The registry intentionally contains no publication-plan, publication-receipt,
authority-currentness-observation, worker-assignment, worker-requirement, or
enforcement-plan record families. A repository synchronization observation is
evidence only and cannot be bound as positive authority.

`REPOSITORY_SYNC_OBSERVATION.remote_commit` is conditionally present. It is
required for `REPOSITORY_SYNCED`, `LOCAL_AHEAD_REMOTE`, `REMOTE_AHEAD_LOCAL`,
`REMOTE_DIVERGED`, and `EXTERNAL_STOP_PROHIBITS_SYNC`; it may be omitted for
`REMOTE_SYNC_UNKNOWN` and `REMOTE_SYNC_BLOCKED`; and it is forbidden for
`NO_CANONICAL_REMOTE`. Unknown and blocked classifications remain deny-only
for substantive execution. `LOCAL_ONLY` remains a repository-binding policy,
not a fabricated remote observation.

`DISTRIBUTION_ORIGIN.governing_sources` is valid only when its path set equals
the exact `fixed_governing_source_paths` set in the structured registry:
`project-runtime/RECORD-GRAMMAR.md`,
`project-runtime/GOVERNING-RECORD-CONTRACTS.md`,
`project-runtime/RECOVERY-CONTRACTS.md`,
`project-runtime/AUTHORITY-EVALUATOR.md`,
`project-runtime/HUMAN-CONTROL.md`, and
`bootstrap/GENESIS-ADMISSION.md`. Each member is digest-bound to the exact
selected-distribution bytes; capability exports remain outside this set.
