## 1. Summary

P2.4 adds two cold-only threshold-share formats:

- Shamir39 splits a valid BIP-39 phrase into `shamir39-p1` mnemonic shares,
  accepting the legacy `shamir39` marker when combining.
- Raw SSS splits even-length hexadecimal data using the secrets.js-compatible
  share format over GF(2^n), with configurable field sizes from 3 through 20
  bits and an 8-bit / 128-bit-padding compatibility default.

The source, generated shares, combine inputs, reconstructed candidate, and
timers stay inside the opaque cold frame. The UI masks shares and results by
default, provides only a user-triggered 30-second reveal, and clears every
secret-bearing surface on lock or panic teardown. No message type, clipboard,
download, print, storage, passphrase, or wallet-device transport path was
added.

Nonconstant polynomial coefficients are sampled independently and uniformly
from the complete field, including zero. This is an intentional generator
distribution decision recorded in ADR-0038: the pinned upstream generators
reject zero, but their share encodings and combiners remain compatible with
Coldbox output. The fresh vectors and exhaustive GF(8) checks below cover the
resulting policy directly.

The canonical clean-clone build has Git metadata available: `scripts/build.js`
embeds the most recent commit date touching `src/`, `scripts/`, or `vendor/`.
The current artifact is therefore the date-bearing `c01bfb39…` result below.
The larger `08ca146a…` result is only the documented unknown-date fallback
when the Git subprocess cannot run; it is not the normal clean-clone artifact.

## 6. Security review notes

- `src/cold/shamir.js` contains no `postMessage`, `fetch`, XHR, WebSocket,
  storage, `eval`, `new Function`, or `Math.random` surface.
- `src/cold/main.js` calls `clearShamirSession()` through the shared vault
  session teardown before clearing the cold session state.
- The warm realm has no `__coldboxShamir` binding; browser coverage checks this
  directly from the parent page.
- The raw result and Shamir39 result are masked even after successful combine.
  Revealing is separate, timed, and manually hideable.
- The implementation does not claim share authenticity. A wrong or malicious
  share can yield an incorrect candidate; the guide explicitly requires BIP-39
  checksum/fingerprint or independent raw-hex verification.
- The complete-field sampler includes zero and therefore supports the standard
  below-threshold field-segment secrecy claim under an independent uniform
  CSPRNG and public parameters. This claim excludes share authenticity, host
  compromise, public metadata, and a separate BIP-39 passphrase.
- Temporary upstream checkout directories were removed after source review:
  `.source-shamir39` and `.source-secretsjs`. No upstream checkout is staged.

### Historical blocking cryptographic finding (resolved in round 5)

At the round-4 review head, `src/cold/shamir.js` sampled each nonconstant
coefficient with a loop that rejected zero. That was a substantive distribution
choice: below the threshold, the share distribution was not the full uniform
coefficient space. The maintainer subsequently chose the full-uniform policy,
recorded it in ADR-0038, and added the implementation and independent vectors
documented in round 5 below.

## 12. Remediation of R5-F1 — canonical clean-clone build evidence

R5-F1 is resolved as an evidence/semantics correction only. No product source,
security gate, share encoding, or full-uniform coefficient-policy behavior was
changed.

### Diagnosis

`readBuildCommitDate()` in `scripts/build.js` runs:

```text
git log -1 --format=%cI HEAD -- src scripts vendor
```

When that command succeeds with non-empty stdout, the build embeds the
date-bearing source value. On the exact PR head, a fresh clone returned status
0 and:

```text
2026-08-12T19:26:15-07:00
```

and the built HTML contained:

```text
var PROVENANCE_BUILD_DATE = "2026-08-12T19:26:15-07:00";
```

That is the canonical clean-clone behavior. The resulting artifact is
`c01bfb3946487ef81d2fdd3ca0b1dc537ab437ba02147f7b7678dc1eeaed0e66`,
2,263,833 bytes.

The `08ca146a…` artifact is not a second normal Git-capable build. It is the
fallback artifact produced when `spawnSync('git', …)` returns an error such as
`EPERM`; the HTML then contains:

```text
var PROVENANCE_BUILD_DATE = "unknown (no git commit metadata available)";
```

That fallback string is 17 bytes longer than the date-bearing value, which
accounts for the exact 17-byte difference between 2,263,850 and 2,263,833.
The fallback remains intentional and fail-soft because the build-date field is
informational, but it must not be presented as the canonical clean-clone
artifact.
