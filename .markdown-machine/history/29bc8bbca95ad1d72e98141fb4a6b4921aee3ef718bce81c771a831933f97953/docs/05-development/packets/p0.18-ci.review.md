## 7. Findings

### F1 — Blocking: CI builds a shallow synthetic PR merge, so its artifact hash does not match a full-history local build

**Severity:** blocking acceptance defect
**Location:** `.github/workflows/ci.yml:48,199,239` (`actions/checkout@v4` with default checkout/history behavior); `scripts/build.js:80-110`; P0.18 acceptance criterion in `docs/05-development/ROADMAP.md`

**Observed:**

The exact-head GitHub Actions run is associated with PR head:

```text
64fc0f6b9e9031d3f1955f89de41e35cd4fb9a8b
```

but the actual hosted checkout log says:

```text
fetch-depth: 1
HEAD is now at 69268de
Merge 64fc0f6b9e9031d3f1955f89de41e35cd4fb9a8b
into 3c0b50289d3cfb88bdf6810503ad72b3a435eb59
```

The workflow therefore builds GitHub's synthetic pull-request merge with only one commit of history, not the exact branch tip with its relevant history.

That matters because `scripts/build.js` intentionally embeds a git-derived build date:

```js
const BUILD_DATE_SOURCE_PATHS = Object.freeze(['src', 'scripts', 'vendor']);

git log -1 --format=%cI HEAD -- src scripts vendor
```

and falls back to `"unknown (no git commit metadata available)"` when the needed history is unavailable.

The real CI artifacts are internally valid and cross-OS-identical:

```text
Ubuntu:
e6b94f72d2b89c54bf6f772efdf65f0bda8da6216f10d9d1857bea77325ffb2e

Windows:
e6b94f72d2b89c54bf6f772efdf65f0bda8da6216f10d9d1857bea77325ffb2e
```

Two fresh full-history local builds on the exact PR tip, including a second path/timezone/locale clone, instead reproduce:

```text
8891368cf8122dfe553ab4aa7fba7b976007b57d0c73b2dec4ae7a2449eeed59
```

Thus the workflow proves only that two hosted runners with the same shallow/synthetic checkout agree with each other. It does **not** satisfy the roadmap's required “CI hash matches a local build.”

This is also fragile on non-PR triggers: `actions/checkout` defaults to `fetch-depth: 1`, while the build's provenance query explicitly depends on historical path information.

**Expected:** CI must build the same source/history model used by a normal exact-tip local checkout so its artifact hash equals the independently reproduced local hash.

**Required action:** Make checkout semantics explicit for every build-producing job. At minimum, fetch enough history for `git log -1 ... -- src scripts vendor` to resolve identically and, on PR events, checkout the actual PR head SHA rather than GitHub's synthetic merge if the acceptance claim is branch-tip reproducibility. Then rerun real Actions and independently compare the downloaded Ubuntu/Windows artifacts to a fresh pinned-Node full-history local build.
