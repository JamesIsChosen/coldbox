# P0.20 — In-app Appropriate Legal Notices (AGPLv3 §5(d))

Branch: `p0.20-legal-notices`
Roadmap item: [ROADMAP.md — P0.20](../ROADMAP.md)

## 1. Summary

AGPLv3 §0 defines "Appropriate Legal Notices" (copyright notice, no-warranty statement, that recipients may convey the work under this licence, how to view a copy of it) and §5(d) requires an interactive UI to display them; Coldbox has one, so [ADR-0018](../adr/0018-agplv3-license.md) filed this as a Phase 0 item and a release gate. This PR adds a "Legal notices" section to the existing Provenance panel (built by P0.16) stating all four elements, embeds the repository's own `LICENSE` file into the build byte-for-byte, and adds the Node test that asserts the two can never drift.

## 2. Scope

**In scope:** the Provenance panel's new "Legal notices" section (`src/index.html`, `src/main.js`, `src/styles.css`); `scripts/build.js`'s `readLicenseText()` and its wiring into the assembled document; `test/legal-notices.test.js` (byte-identity plus four negative/regression tests); `scripts/run-browser-harness.js`'s new `verifyLegalNotices()` and the `copyBuildInputsInto()`/`createBuildRoot()` fixes needed to keep every isolated-build-root test passing now that `build.js` reads `LICENSE` from the project root; a new three-depth glossary entry ("Appropriate Legal Notices"); CHANGELOG and ROADMAP updates.

**Not in scope, deliberately:** `release-checklist.md` already carries the P0.20 gate — it was added in the relicensing commit (`6fdb4a0`) that filed this roadmap item, so no further edit was needed there. No ADR added; this item is fully covered by citing [ADR-0018](../adr/0018-agplv3-license.md), which already anticipated it and named the provenance panel as its home. No change to the message schema, CSP, vault format, or any cryptographic path.

## 6. Test evidence

- **`test/legal-notices.test.js`** (new, 9 tests):
  - Byte-identity of embedded `PROVENANCE_LICENSE_TEXT` against the repository's `LICENSE`, compared as `Buffer`s (not `===` on strings).
  - Negative: build against a deliberately tampered `LICENSE` embeds the tampered text (not the real one) and differs from the real `LICENSE` — proves the byte-identity assertion is actually discriminating, not vacuously true.
  - Negative: build refuses (non-zero exit) if the `__COLDBOX_LICENSE_TEXT__` placeholder is removed from `main.js`.
  - Negative: build refuses if the placeholder appears twice (mirrors the existing `__COLDBOX_EXPECTED_HASH__` duplicate-placeholder test in `test/provenance.test.js`).
  - SPDX identifier matches `package.json`'s `license` field.
  - Copyright/no-warranty/may-convey statements present in rendered markup.
  - Full licence text present in the DOM (not just in a hidden/late-populated state) with the AGPLv3 header/footer markers.
  - Two builds under different locale/timezone embed identical licence text.
- **Vectors:** the "vector" here is the repository's own `LICENSE` file, which is the FSF's unmodified GNU AGPLv3 text (confirmed identical to the FSF's published text by an earlier, unrelated packet in this project's history — see `docs/05-development/packets/` git history around commits `68e042b`/`e41f9d9`). No cryptographic vectors are involved in this item.
- **Fixed 8 pre-existing test regressions this change introduced** (all in `test`, none touching `src`/`scripts` behavior beyond what's described above):
  - `test/build.test.js`, `test/help-content.test.js` (×2), `test/provenance.test.js`: their `createBuildRoot()`-style fixtures copy `scripts`/`src`/`vendor`/`docs` into an isolated temp directory and invoke `build.js` there; since `build.js` now reads the repository's `LICENSE` directly, every one of these fixtures needed a `fs.copyFileSync` for `LICENSE` added, or the isolated build failed with `ENOENT`. Fixed in all four files.
  - `scripts/run-browser-harness.js`'s shared `copyBuildInputsInto()` helper (used by `verifyDevOnlyDependency()` and, now, `verifyLegalNotices()`) had the identical gap — fixed the same way. This is the same class of bug as P0.17's F1 finding (that time it was a missing `docs` directory); flagging it explicitly here since I did not catch it until running the full suite, exactly the kind of thing a reviewer should double-check.
  - `test/build.test.js`'s "no machine paths in build output" regression check (`NO_MACHINE_PATHS`) false-flagged three real, benign occurrences of `s:\n` inside the embedded licence text (ordinary AGPLv3 prose ending a line with a colon, e.g. "...supplement the terms of this License with terms:\n") as a Windows-drive-letter-path leak. This is a genuinely new class of false positive: every value embedded before this PR was either single-line HTML or had no literal newlines in its JSON encoding, so this is the first embedded value whose `JSON.stringify()` output can legitimately contain a bare `\n` escape. I considered extending the check's already-narrow exclusion list (per its own F2 history) to also exclude `\n`/`\r`/`\t`, but rejected that — it would blind the check to real paths like `C:\temp\...`, `C:\repo\...`, `C:\node_modules\...`, which are far more plausible collisions than the already-considered `\u1234` case. Instead, the test now strips the (separately, byte-identity-verified) `PROVENANCE_LICENSE_TEXT` assignment before running the machine-path check, so every other byte of the build — including the code surrounding that assignment — is still checked in full. See the comment in `test/build.test.js` for the full reasoning.

## 8. Assumptions made

- **Copyright holder and year.** The panel states `Copyright (C) 2026 James Kent`. This mirrors the project's former MIT `LICENSE` notice (`Copyright (c) 2026 James Kent`, visible at commit `6fdb4a0^:LICENSE`) and [ADR-0018](../adr/0018-agplv3-license.md)'s explicit statement that "all copyright in the repository is held by the single author named in the previous MIT notice." No other file in the repository currently states this fact in a form suitable for direct reuse (the AGPLv3 `LICENSE` text itself is the FSF's unmodified template and correctly contains no project-specific copyright line — filling one in there would break the byte-identity-to-canonical-AGPLv3-text property a prior packet already established). **What breaks if this is wrong:** if the actual intended holder/year differs, this is a one-line text fix in `src/index.html`'s new `#provenance-legal-notices` article; no test currently pins the exact name (only the shape `Copyright \(C\) \d{4} James Kent`), so a maintainer correction wouldn't require touching the test.
- **Placement of the "Legal notices" article inside the existing panel** (appended after "Verify this file," the last existing article) rather than at the top. The roadmap and ADR-0018 say the notices belong in the provenance panel but don't specify ordering within it. Minor; recorded here per AGENTS.md's guidance on layout-level decisions.
- **`<details>` disclosure, not a modal or a separate route**, for the full licence text. Chosen because it's a native, keyboard-and-screen-reader-accessible HTML control needing no additional CSP surface (no new inline script beyond what already exists) and is populated eagerly (on load, not on first open) so the browser harness and any accessibility tooling can find the text without simulating a click — though the harness does also simulate the click, to prove a real user path works, not just that the text exists somewhere in the DOM.
- **`readLicenseText()` reads raw UTF-8 bytes with zero normalization** (no BOM strip, no CRLF→LF), deliberately diverging from every other `readSource()`-based file in `build.js`. Confirmed safe because the repository's `LICENSE` is already LF-only, BOM-free, ASCII text (checked directly: `file LICENSE` reports "ASCII text", zero `\r\n` occurrences). If a future edit to `LICENSE` introduced CRLF or a BOM, this build would embed it verbatim — which is *correct* per the "byte-identical" acceptance criterion, not a bug, but would also make `npm run lint`'s LF-only-source-file check inapplicable to `LICENSE` (that check only covers `src`/`scripts`, not the repository root), so an editor auto-CRLF-ing `LICENSE` would slip through undetected as a distinct hygiene gap. Flagged as worth a future doc-hygiene check if it ever becomes a real problem; not fixed here as it is out of this item's scope.

## 9. What to scrutinise

- **The browser-harness check (`verifyLegalNotices()`) has never actually run.** I wrote it to the same conventions as the existing `verifyProvenancePanel()`/`verifyHelpFramework()` (real `page.context().setOffline(true)`, `waitFor({ state: 'visible' })`, clicking the `<details>` summary as a real user would), and `node --check` confirms it parses, but I cannot rule out a locator typo or a real DOM-ordering issue that only a real Playwright run would surface. This is the single largest gap in this packet's evidence — please run `npm run test:browser` for real before merging, or at minimum re-read the function for logic errors a static check can't catch.
- **The `NO_MACHINE_PATHS` test fix** (§6, last bullet). I'm confident in the reasoning (excluding bare `n`/`r`/`t` would be a net loss of real detection power), but the "strip the byte-identity-verified substring before checking" approach is a new pattern in this test file, and a reviewer should confirm the regex used to strip it (`/var PROVENANCE_LICENSE_TEXT = "(?:[^"\\]|\\.)*";/`) can't itself be tricked into over-matching or under-matching if the licence text ever contained an unescaped `"`. It can't today (JSON.stringify escapes every `"` in the string as `\"`, and the non-greedy-alternation pattern `(?:[^"\\]|\\.)*` is the same construction the repository already uses elsewhere for this exact purpose, e.g. `test/provenance.test.js`'s `provenanceBuildDate()`), but it's worth a second pair of eyes.
- **The bundle-size delta measurement's baseline.** "1,040,074 bytes" for pre-P0.20 `main` was measured by `git archive main | tar -x` into a scratch directory and building there, not by `git stash`/`git checkout` on the working branch (to avoid disturbing in-progress work per the git-safety guidance I was given). I'm confident in the method but a reviewer can trivially reproduce it: `git worktree add /tmp/baseline main && cd /tmp/baseline && node scripts/build.js && wc -c build/coldbox.html`.

### F2 (advisory): fixed — `NO_MACHINE_PATHS` now independently scans the licence text's real bytes, plus a negative regression

**What the reviewer found:** `stripEmbeddedLicenseText()` removed the entire `PROVENANCE_LICENSE_TEXT` JSON assignment from the whole-document machine-path scan. Byte-identity to the repository's `LICENSE` (`test/legal-notices.test.js`) proves the *build* matches its *input*; it says nothing about whether that input is itself path-free. The reviewer proved the resulting blind spot by appending a literal Windows path to a disposable copy of `LICENSE` and getting 21/21 green.

**Fix (commit `4800460`):** added `extractEmbeddedLicenseText()`, which pulls the JSON string literal back out of the built HTML and `JSON.parse()`s it to the real, unescaped text, then asserts that against `NO_MACHINE_PATHS` *before* the existing whole-document scan (which still runs afterward, with the assignment stripped, exactly as before — so no coverage is lost, only added). Once unescaped, real licence prose never produces the `letter:\` + escape-sequence shape that motivated the original strip — that collision is an artifact of `JSON.stringify()`'s escaping, not of the licence text itself — so scanning the raw text directly does not reintroduce the original false positive.

Also added a negative regression, per the reviewer's explicit required action, that reproduces the reviewer's exact attack end-to-end (build with a machine path appended to `LICENSE`, in an isolated root, and assert the resulting build's embedded licence text is flagged). It is a standalone generated check script, not a copy of `test/build.test.js` itself — an earlier draft copied `test/build.test.js` into the isolated root and ran it with `node --test`, which recursively re-ran this very test inside the child process, which spawned its own child, and so on; the sandbox `SIGKILL`ed that attempt after roughly a minute of runaway recursive builds. The final version avoids that entirely by writing a small, self-contained script containing only the two real assertions under test.

```
$ node --test --test-concurrency=1 test/build.test.js
...
ok 1 - build assembles one HTML file and emits its SHA-256 sidecar
ok 2 - the no-machine-paths guard flags real absolute paths, including ones shaped like a JSON escape, but not the actual JSON escapes jsonScriptLiteral emits (P0.17 review F2)
ok 3 - a machine path smuggled in through LICENSE makes the build test suite fail non-zero (P0.20 review F2 negative regression)
...
1..13
# tests 13
# pass 13
# fail 0
```
