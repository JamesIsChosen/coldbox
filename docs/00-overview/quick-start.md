# Quick start

Ten minutes from download to a working vault. Read [what is this?](what-is-this.md) first if you haven't.

> ⚠️ **Pre-release · not audited.** This guide describes the current product contract; see the [roadmap](../05-development/ROADMAP.md) for the only authoritative item-level status.

---

## 1. Download and verify

Get `coldbox-v1.0.0.html`, `.sha256`, and `.asc` from the GitHub releases page.

```bash
# macOS / Linux
shasum -a 256 coldbox-v1.0.0.html

# Windows PowerShell
Get-FileHash coldbox-v1.0.0.html -Algorithm SHA256
```

Compare against the `.sha256` file. If they differ, **stop** — you don't have the file you think you have.

Verify the signature too if you can. [Full instructions](../02-security/verification.md).

## 2. Choose where to run it

| Situation | Do this |
|---|---|
| Just exploring | Any computer. Don't enter real seeds |
| Real wallets, real money | An offline machine, or Tails from USB |
| Portfolio only | Any computer. Secrets stay sealed automatically |

The app enforces the distinction: when a network connection exists, the secret half of your vault will not decrypt. You don't have to remember to be careful.

## 3. Open it

Double-click on a supported desktop browser. On Android, open from the Files app. Direct local HTML execution from iOS Files is currently a blocked portability target; see [ADR-0010](../05-development/adr/0010-ios-local-html-execution.md).

Check the **Network & sealed-realm status** across the top:

- 🟢 **No external reachability detected · cold realm sealed** — active warm-shell probes failed consistently; secret-capable mode may be offered, but this is **not proof of a physical airgap**
- 🟡 **Online · secrets sealed** — at least one reachability probe succeeded
- 🟡 **Checking / unknown · secrets sealed** — Coldbox has not established an offline result and therefore fails online-safe
- 🔴 **Cold-realm isolation/CSP failure · locked down** — the security boundary failed; do not proceed

`navigator.onLine` and interface-change events are only hints that trigger rechecks. The warm shell performs the probes; the cold realm still has `connect-src 'none'` and cannot make them.

Then check the capability panel, which reports what your browser supports. Do not treat an iOS Files Quick Look preview as an application run.

## 4. Create your vault

**Vault → Create new.**

1. Give the vault a **public name**. It becomes part of the filename/library display, so never put a seed, passphrase, account number, or other secret in it.
2. Inside the sealed realm, enter the **new unlock phrase twice**. The confirmation field exists only during creation; normal unlock asks once. A mismatch refuses creation.
3. Choose the KDF profile after benchmarking the device(s) that must open the vault.

Your unlock phrase is the main protection against an attacker who steals the `.cbx`. Use a strong Diceware phrase and store it physically. Until recovery shares ship, losing it means losing access.

Every new vault also gets a random, non-secret **Vault ID** generated by the cold realm. It identifies the vault across filenames and devices. It is deliberately **not a device fingerprint**: several vaults can live on one device, and a vault must keep the same identity when copied to another machine.

## 5. Save it

A new vault is shown as **UNLOCKED · NOT SAVED** until encrypted bytes have been handed to a save path. **Save vault** is a primary action, not something hidden among export utilities. Depending on the browser you can use File System Access, a download, or the manual base64/QR path. A verified File System Access write becomes **Saved · verified**; a download/manual handoff becomes **Saved · unverified** until reopened or verified. Saving hands only encrypted `.cbx` bytes to the warm shell, preserves the same Vault ID across every generation, and does not weaken cold-realm zeroization.

A normal user-requested lock warns if the current vault is unsaved or has only an unverified save/export and offers **Save first / Lock without saving / Cancel**. The visible cold-realm **Request lock** button uses that same warm-shell confirmation gate; it does not bypass it. Emergency paths — panic hide, timeout, network-mode transition, or a cold-realm health failure — lock immediately and never wait for storage. The sealed realm then zeroizes its session material and working vault bytes.

After saving, reload from the **Vault Library** and unlock again. Chromium-based browsers may let you grant a vault folder; other browsers use a multi-file picker. Coldbox only detects vaults inside the files/folder you explicitly grant — a local HTML page cannot silently scan your disk. Select the named vault first, then enter its unlock phrase **once** inside the sealed realm. Test with at least two named vaults so you know which one is active.

Keep the app and vault files together on removable media if that fits your workflow, and keep a second verified copy elsewhere.

## 6. Record your first wallet

You don't need to create anything new — start by recording what you already have.

**Registry → Add wallet.** Enter a label, the device holding it, and its master fingerprint (your hardware wallet can display this). Add the xpub if you have it, which lets Coldbox derive addresses for verification and balance lookups.

Notice you haven't entered a seed phrase. You don't need to. The registry is fully useful with no secrets at all.

## 7. Verify something

This is the point of the whole tool. **Devices → Verify → Receive address.**

Enter your account's xpub, pick the script type, and generate the first few addresses. Compare against what your hardware wallet displays. If they match, your wallet software is telling you the truth.

If they don't, you may have just caught malware. [Full guide](../03-guides/verify-a-hardware-wallet.md).

## 8. Record a backup

**Backup Lab → Record existing backup.** Where is your metal plate? Who else knows? When did you last confirm it's readable?

The Backup Health dashboard now tracks it and will flag it when verification is overdue.

## Three things that lose people money

**Untested backups.** You find out it's wrong when you need it. The app makes you reconstruct from your shares before marking a backup complete — let it.

**Forgotten passphrases.** A BIP-39 passphrase with one character different is a valid, empty, permanently different wallet. Verify the fingerprint before funding it.

**Undocumented derivation paths.** "My coins vanished" is nearly always "my wallet is looking at a different path." Record the path for every wallet.
