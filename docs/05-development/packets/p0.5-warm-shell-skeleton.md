# PR packet: P0.5 — Warm shell skeleton

## 1. Summary

P0.5 adds the responsive outer document described by the roadmap: a desktop navigation rail, mobile tab bar, route placeholders, and dark/light mode. It keeps all routes deliberately feature-free and reserves secret-facing work for the cold realm item that follows. The built artifact remains one hash-pinned HTML file with the documented warm-shell CSP.

## 2. Scope

### In scope

- Responsive warm-shell layout from 360px through desktop widths
- Desktop navigation rail with Workspace, Tools, and Reference sections
- Mobile tab bar with an accessible overflow menu
- Hash-based routing for every documented shell destination
- Dark/light theme switch with non-secret `localStorage` preference persistence and a safe dark default
- CSP regression coverage for the canonical warm-shell allowlist
- Browser-harness coverage in Chromium and Firefox over `file://`
- Roadmap and changelog updates

### Deliberately out of scope

- Cold-realm iframe creation, sandboxing, handshake, or secret fields (P0.6+)
- Vault, portfolio, price, derivation, backup, or QR functionality
- Real-device matrix certification (P0.19)
- New external hosts, runtime dependencies, message types, or ADRs

## 5. Security impact

- Realm boundary: **No**. This item does not create an iframe, handle a secret, or add a cross-realm message.
- Message schema: **No new message type**.
- CSP: **Yes, outer warm-shell policy is carried into the shell and regression-tested.** The policy retains `default-src 'none'`, hash-pinned script/style sources, `form-action 'none'`, `base-uri 'none'`, `object-src 'none'`, and the canonical `connect-src` allowlist.
- New `connect-src` hosts: **None**. The allowlist matches [csp-policy.md](../../02-security/csp-policy.md), including the existing localhost entries.
- If the implementation were wrong, the immediate risk would be an untrusted or non-reproducible warm shell, an unintended network allowlist change, or a misleading route surface. No secret-bearing code is present here, and the next item must still establish the sealed realm before secret operations can exist.

## 6. Test evidence

### New and changed tests

- `scripts/run-browser-harness.js` now checks the warm-shell build state, default route, route changes, theme switching, desktop rail visibility, mobile tab visibility, overflow-menu routing, and horizontal fit at 360px.
- `test/build.test.js` now asserts the documented warm-shell `connect-src` host list and required fail-closed directives.
- Existing tamper checks were updated from the old skeleton marker to the warm-shell marker; a byte-altered inline script remains rejected in both engines.

### Negative tests

- The browser harness deliberately alters one byte of the built inline script. Chromium and Firefox report `script-src` and do not set the warm-shell state.
- A temporary LF-normalized source tree with `eval` appended to `src/main.js` produced `ExitCode : 1` and `Forbidden construct "eval"`; the build refused to continue.
- The existing CSP fixture and reusable frame checks continue to report deliberate policy violations and blocked network primitives.

### Review note

The first browser pass exposed that the overflow menu was unhidden by JavaScript but still had `display: none` from the base stylesheet. The CSS was corrected, the duplicate mobile header control was removed, progressive fallbacks were added for older browsers, and the full suite was rerun successfully.

### Not tested

No cryptographic vectors apply to this item. No real iOS Safari, Android Chrome from Files, macOS Safari, Linux Firefox, Tor Browser, or physical device was available; those remain untested rather than inferred.

## 8. Assumptions made

> **Assumed:** A hash in the URL fragment is the stable routing contract for the shell.
> **Basis:** The app must run from `file://`, and the spec requires routing without a server; `src/main.js` normalizes unknown fragments to `#dashboard`.
> **Not verified on:** Safari and mobile browsers.
> **If wrong:** A browser-specific history restriction could leave the visible route and fragment out of sync; the navigation remains link-based and the fallback assigns `window.location.hash`.

> **Assumed:** A 720px breakpoint is a suitable boundary between the rail and mobile tab bar.
> **Basis:** It keeps the full rail usable on compact desktop/tablet widths while preserving thumb-reachable navigation on phones; the spec does not prescribe a breakpoint.
> **Not verified on:** The full physical device matrix.
> **If wrong:** A particular tablet may receive the less comfortable navigation mode; P0.19 is the place to record that platform result and adjust the breakpoint if needed.

> **Assumed:** `localStorage` is optional for theme preference.
> **Basis:** The portability contract allows UI preferences in local storage and says it may be unavailable under `file://` on iOS; the shell catches storage errors and defaults to dark mode.
> **Not verified on:** iOS Safari from Files.
> **If wrong:** The preference will not persist, but the shell remains usable and no secret is stored.

## 9. What to scrutinise

- The route normalization and duplicate-link active-state logic in `src/main.js`, especially under `file://` on browsers not covered by the harness.
- The CSP allowlist in `src/index.html` against the canonical security document; this item intentionally adds no host.
- The mobile breakpoint, overflow menu, safe-area padding, and progressive CSS fallbacks on older Safari and Android browsers.
- The fact that all placeholders are public shell text and no secret field or cold-realm shortcut has been introduced accidentally.

## 10. Self-assessment

- The real-device matrix is not complete; the roadmap explicitly assigns that confirmation to human-required P0.19.
- The shell has no feature behavior beyond routing and theme preference; later items must not treat its placeholders as proof that those features exist.
- A browser with unavailable `localStorage` loses theme persistence by design, but does not fail to render.
- No structural decision was made beyond implementing the accepted two-realm navigation surface, so no ADR was added.
- Follow-up: P0.6 must replace the Vault placeholder with the fail-closed cold-realm bootstrap while preserving the public shell boundary.
