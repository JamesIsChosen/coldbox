# PR packet: P1.2 — Entropy Health Meter and Bias Analyzer

## 1. Summary

Implements the next available roadmap item, [P1.2](../ROADMAP.md#phase-1--core-wallet), inside the sealed cold realm. Entropy Health now analyzes physical/manual dice, discard-dice, coin, card, and hex observations with claimed bits, an observed empirical min-entropy estimate, per-symbol frequencies, chi-square evidence, a runs test, lag-one serial correlation, and deterministic pattern warnings. Device-RNG simulations are counted separately and excluded from every diagnostic. Cards are treated as without-replacement permutations, so iid tests and measured min-entropy are explicitly unavailable for them.

The analyzer is advisory. P1.1's integer possibility-space accounting remains the authority for independent-source credit and mixing. No entropy-health value or message crosses the cold/warm boundary.

## 2. Scope

**In scope:**

- `src/cold/entropy-health.js` — DOM-free, network-free statistical analyzer
- `src/cold/main.js`, `src/cold/index.html`, and `src/cold/styles.css` — cold-realm wiring and UI
- `scripts/build.js` — vendored inline cold component assembly
- `scripts/run-browser-harness.js` — Chromium/Firefox file-based assertions for simulations, manual samples, runs/pattern warnings, and card-permutation handling
- `test/entropy-health.test.js` — independent-vector and negative coverage
- [ADR-0027](../adr/0027-entropy-health-statistical-diagnostics.md) and its index entry
- [SPEC.md](../../01-spec/SPEC.md), [entropy-and-strength.md](../../04-reference/entropy-and-strength.md), [first-wallet.md](../../03-guides/first-wallet.md), and the three-depth [glossary](../../00-overview/glossary.md)
- `CHANGELOG.md` and `ROADMAP.md` (`[ ]` → `[~]`)

**Deliberately out of scope:**

- A confidence-bound or bias-corrected entropy estimator. P1.2 labels the maximum-frequency result as an empirical observed estimate; a stronger estimator needs a separate specification and sampling protocol.
- Using diagnostics as a P1.1 security gate or as proof that a platform CSPRNG is sound.
- Applying iid frequency, runs, or serial-correlation tests to card permutations.
- P1.3 Seed Forge, BIP-39 generation, or any secret-bearing hand-off.
- The physical device matrix. This packet records the automated file-based browser result and marks physical/mobile platforms untested.

| Criterion | How satisfied | Test/evidence |
|---|---|---|
| Entropy Health Meter | Cold-realm panel stays live during collection and shows health state, samples, claimed bits, observed measured estimate, and source frequencies. | Chromium and Firefox `verifyEntropyLab()` assertions; build contains the panel. |
| Bias Analyzer frequency and claimed/measured values | Finite-alphabet frequency table and empirical maximum-frequency estimate; simulation provenance is excluded. | `analyze() reports exact frequencies and claimed-versus-measured min-entropy`; browser simulation/manual assertions. |
| Chi-square and p-value | Pearson statistic, upper-tail p-value, `alpha=0.01`; unavailable until every expected bin has at least five observations. | NIST-derived statistic/critical-value test; skew and small-expected-count negative test; browser output. |
| Runs test | NIST binary Wald-Wolfowitz formulation, midpoint projection for multi-symbol sources, explicit sample/proportion preconditions. | Alternating/grouped independent vectors; browser `runs=20` warning. |
| Serial correlation | NIST lag-one correlation and 95% advisory band; constant and card cases are unavailable. | `[1,2,3,4,5]` vector and zero-variance negative test; browser card assertion. |
| Pattern warnings | Long runs, ordered sequences, alternation, and repeated blocks are deterministic advisory warnings. | Four-pattern unit vector and browser alternating-pattern assertion. |
| Honest source handling | Device-RNG simulations are excluded; cards are without-replacement and do not receive iid tests or a fabricated measured value. | Card/simulation unit tests and final Chromium/Firefox harness. |
| Fail closed | Malformed alphabets, symbols, options, and empty observations throw; underpowered valid tests return explicit unavailable reasons. | Negative analyzer tests for invalid symbols, empty input, ambiguous claims, and non-boolean replacement mode. |

## 5. Security impact

- **Randomness:** yes, in the sense that this code reports diagnostics about recorded physical/manual source values. It does not generate key material, change P1.1's `BigInt` accounting, or change `mix()`.
- **Realm boundary:** touched only by adding a cold-realm component. The analyzer is assembled inside the sealed realm and no new message type or field was added.
- **CSP/network:** no new `connect-src` host; the analyzer has no network API and the cold policy remains `connect-src 'none'`.
- **Secrets:** no mnemonic, private key, xprv, passphrase, or decrypted vault data is read or carried. No analyzer result crosses to the warm shell.
- **If wrong:** a user could be misled about evidence in a physical recording, especially by treating an empirical estimate or passing test as proof. The UI and ADR explicitly state that finite-sample diagnostics are advisory and cannot establish platform CSPRNG integrity. The stronger P1.1 entropy accounting is unchanged.

## 6. Test evidence

### New tests

`test/entropy-health.test.js` loads the raw cold module in a DOM-free VM and covers:

- exact frequencies and claimed-versus-observed empirical min-entropy;
- chi-square statistic, degrees of freedom, upper-tail p-value interval, and alpha decision;
- strong skew detection and refusal when expected counts are below five;
- alternating and grouped binary runs;
- lag-one serial correlation and zero-variance unavailability;
- all four deterministic pattern warning classes;
- without-replacement card handling; and
- malformed inputs and ambiguous options failing closed.

### Independent references

The chi-square statistic and critical-value boundary are checked against the [NIST chi-square goodness-of-fit reference](https://itl.nist.gov/div898/handbook/eda/section3/eda35f.htm). The runs formula is checked against [NIST's runs-test definition](https://www.itl.nist.gov/div898/handbook/eda/section3/eda35d.htm), and the lag-one correlation/band against [NIST autocorrelation material](https://www.itl.nist.gov/div898/handbook/eda/section3/eda35c.htm) and its [confidence-band reference](https://www.itl.nist.gov/div898/handbook/eda/section3/autocopl.htm). The broader statistical-test context is [NIST SP 800-22 Rev. 1a](https://nvlpubs.nist.gov/nistpubs/legacy/sp/nistspecialpublication800-22r1a.pdf).

These are diagnostics rather than cryptographic vectors; the tests intentionally assert independently computed statistics and published preconditions, not a claim that the implementation can prove randomness.

### Negative evidence

- Invalid symbols outside the configured alphabet throw.
- Empty observations throw.
- Ambiguous `claimedBits` plus `claimedBitsPerSymbol` throws.
- Non-boolean `withoutReplacement` throws.
- Expected-counts-below-five, too-small runs samples, skewed runs proportions, constant correlation, and cards return explicit unavailable reasons.

## 8. Assumptions made

- The roadmap's one-line P1.2 item is accepted against SPEC §11.1a because it contains no detailed acceptance block; ADR-0027 records the missing operational definitions rather than silently inventing them in code.
- P1.2 is advisory and does not block P1.1 mixing. Seed Forge does not exist yet, so there is no generation gate to wire; P1.3 must consume the existing P1.1 strength/accounting contract and decide how any future user acknowledgement is represented.
- Internal finite-alphabet symbols remain zero-based because that is the P1.1 session representation; UI labels preserve physical notation such as die faces `1`–`6` and discard outcomes `1`–`4`.
- The multi-symbol runs test uses the alphabet midpoint projection specified in ADR-0027. It is one clearly labeled diagnostic, not a claim that it is the only valid multi-symbol test.
- The empirical maximum-frequency estimate is intentionally not a lower confidence bound. This is why the code calls it an estimate and the documentation warns that finite samples can miss a high-probability outcome.
- Cards can span multiple shuffles, so the analyzer conservatively treats the selected card stream as without-replacement and leaves iid tests unavailable across the whole selected stream.

## 9. What to scrutinise

- The regularized-gamma implementation used for chi-square upper-tail p-values, especially extreme tails and large alphabets.
- The exact mapping from each P1.1 source's stored representation to analyzer symbols, including the zero-based dice/discard values and the card pool-size claimed-bit calculation.
- The distinction between an empirical observed estimate and a true min-entropy lower bound; a future edit must not turn the displayed number into a guarantee.
- The decision that a chi-square flag alone makes the health state marginal, while runs/correlation/pattern warnings remain advisory evidence and do not alter P1.1.
- The absence of physical/mobile device verification noted in §7.

## 10. Self-assessment

- **What might be wrong:** The gamma-tail approximation has not been compared against a second numerical library at every extreme value. The multi-symbol midpoint runs projection and deterministic pattern thresholds are engineering choices, not universal standards.
- **What was not done:** No physical iOS, Android, macOS, or Tor run; no native desktop Chrome/Firefox run; no confidence-bound entropy estimator; no P1.3 Seed Forge integration.
- **Known limitations:** A passing statistical test remains absence of detected evidence. The empirical estimate can overstate true source entropy for a finite sample.
- **Follow-up:** P1.3 must connect the existing P1.1 meter/gate contract to BIP-39 generation. Any attempt to use a confidence-bound estimator or statistical result as a generation gate should first amend ADR-0027.
