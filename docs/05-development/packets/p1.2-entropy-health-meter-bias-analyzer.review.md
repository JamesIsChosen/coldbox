### F3 - Runs-test normal approximation is reported outside the cited NIST large-sample precondition

**Severity:** blocking statistical correctness

**Location:**
- `src/cold/entropy-health.js`, `MIN_RUN_SAMPLE_COUNT`, `binaryRuns()`
- `docs/05-development/adr/0027-entropy-health-statistical-diagnostics.md`, decision 4
- `test/entropy-health.test.js`
- `scripts/run-browser-harness.js`

**Observed:**

Production requires only:

```text
sampleCount >= 20
```

plus a proportion-skew check before calculating a normal z-score and p-value.

A balanced 20-symbol sample therefore has `n1 = 10`, `n2 = 10` and is reported as available. The reviewer probe reproduced:

```json
{
  "n1": 10,
  "n2": 10,
  "available": true,
  "runs": 20,
  "zScore": 4.135214625627066,
  "pValue": 0.0000354623074878061
}
```

The NIST runs-test reference cited by ADR-0027 states that the standard-normal comparison is the large-sample treatment when `n1 > 10` and `n2 > 10`; small samples use critical-value tables. The PR's own browser scenario intentionally uses the 20-balanced-flip case, so this is exercised as a supported diagnostic rather than merely reachable dead code.

**Expected:**

The analyzer must not present the large-sample normal-approximation p-value outside the precondition of the reference it claims to implement.

**Required action:**

Require both projected symbol counts to satisfy the chosen large-sample threshold before reporting the normal approximation (for the cited NIST rule, `n1 > 10 && n2 > 10`), or implement a separately justified exact/small-sample runs test. Update ADR-0027, unit vectors, unavailable reasons, and browser assertions to match the chosen rule.

### F4 - Repeated-block detection misses valid non-constant repeated blocks

**Severity:** blocking functional correctness

**Location:**
- `src/cold/entropy-health.js`, `longestRepeatedBlock()`
- `docs/05-development/adr/0027-entropy-health-statistical-diagnostics.md`, decision 6
- `test/entropy-health.test.js`

**Observed:**

ADR-0027 requires a warning for a non-constant block of at least two symbols repeated until at least four values are covered.

`longestRepeatedBlock()` skips every candidate whose first two symbols are equal:

```js
if (values[start] === values[start + 1]) {
  continue;
}
```

That is not equivalent to "the block is constant." A block such as `[0,0,1]` is non-constant even though its first two symbols match.

The reviewer black-box probe used:

```text
[0,0,1,0,0,1]
```

which is the non-constant block `[0,0,1]` repeated twice. Production returned:

```json
"repeatedWarnings": []
```

**Expected:**

Every block meeting ADR-0027's stated non-constant/repetition threshold must be detected, regardless of whether its first two symbols happen to match.

**Required action:**

Replace the first-two-symbol shortcut with an actual whole-block constant check. Add regression vectors for repeated blocks whose first two entries match (for example `[0,0,1,0,0,1]`) as well as existing alternating-style repeated blocks.

**Expected:**

The state machine must have one non-overlapping threshold definition, and all user/developer documentation must describe the implemented definition exactly.

**Required action:**

Choose the canonical threshold semantics (the implementation currently uses the selected target), update SPEC, `entropy-and-strength.md`, `first-wallet.md`, Help content, and tests so the same 128/160/192/224/256 target produces the same named state everywhere.
