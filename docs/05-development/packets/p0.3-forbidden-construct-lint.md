# PR packet — P0.3 Forbidden-construct lint

## 1. Summary

P0.3 adds a build-integrated lint that rejects dynamic execution and module-loading constructs from application source, and rejects network URLs and browser storage from the cold realm source path. Negative fixtures cover every roadmap construct, and the build regression test proves a finding produces a non-zero build failure.

## 2. Scope

In scope:

- Recursive, bytewise-ordered scanning of `src/`.
- Rejection of `eval`, `new Function`, `import`, and `require` in application source.
- Rejection of external URLs and `localStorage` under `src/cold/`, the secret-handling path.
- JavaScript syntax and LF line-ending checks for all application source files.
- Build invocation of the lint after offline vendor verification.
- Six committed negative fixtures, warm-path scope coverage, and build-failure regression tests.
- Roadmap, build documentation, changelog, and PR packet updates.

Out of scope:

- CSP hash-pinning, cold-realm bootstrap, runtime network neutering, and the message schema.
- Cryptography, vault format, derivation, and randomness.
- Browser/device testing; this item changes developer tooling and build admission only.

## 5. Security impact

- Realm boundary: no change.
- Message schema: no change; no message type was added.
- CSP: no change; no `connect-src` host was added.
- Vault format, derivation, cryptographic primitives, and randomness: no change.
- Build admission: yes. If this lint were wrong or bypassed, application source could contain dynamic execution/module loading, or cold-realm source could contain an egress URL or browser storage access. The lint is a fail-closed guard and does not replace independent source review, CSP, or the realm boundary.
- New external host: none.
- New secret-bearing capability: none.

## 6. Test evidence

New tests:

- `test/lint.test.js` runs six committed fixtures: `eval`, `new Function`, `import`, `require`, an external URL, and `localStorage`; every run must exit non-zero and report the matching finding.
- The warm-path fixture proves external URLs and `localStorage` are not globally prohibited outside `src/cold/`.
- The build regression copies the project to a temporary directory, inserts `eval` into application source, and asserts the build refuses to write the artifact.

Independent vectors: not applicable; this change contains no cryptographic behavior.

Negative tests: all six forbidden fixtures fail, and the build integration test fails closed with a non-zero status.

Not tested: browser behavior, device matrix, and second-OS execution. The built HTML bytes are unchanged, and this item does not touch bootstrap, CSP, storage flows, or rendering.

## 8. Assumptions made

**Assumed:** `src/cold/` remains the repository path for all cold-realm and secret-handling source.

**Basis:** the two-realm architecture names the secret realm “cold,” and the build documentation now records this path convention.

**If wrong:** URL and `localStorage` checks would not apply to secret code placed elsewhere; future secret code must be moved under `src/cold/` or the lint prefix list must be updated in the same change.

**Assumed:** Node tooling under `scripts/` may use `require` because it runs outside the application and is only syntax-checked.

**Basis:** the existing build and vendor verifier are CommonJS developer tooling, while the no-`require` rule applies to application source.

**If wrong:** the build tooling would be unable to run; changing that would require a separate toolchain decision.

## 9. What to scrutinise

- The `src/cold/` path boundary: it is the security-relevant scope for URL and storage checks.
- The literal-token rules and their line/column reporting in `scripts/lint.js`.
- The child-process status handling in `scripts/build.js`; a lint error must prevent artifact assembly.
- The distinction between application-source rules and CommonJS build tooling.

## 10. Self-assessment

- The implementation is a conservative textual guard, not a general malicious-code detector; source review and the CSP remain necessary.
- The path convention is explicit but narrow, so future source layout changes must update the prefix list deliberately.
- No second OS, browser, or mobile device was available or needed for this developer-tooling-only item.
- The output artifact remains byte-identical and therefore does not demonstrate runtime CSP behavior; CSP testing belongs to P0.4 and later bootstrap items.
