# PR packet: P0.6 — Cold realm bootstrap

## 1. Summary

P0.6 adds the first sealed cold realm to the warm shell. The build assembles a dedicated `srcdoc` document from `src/cold/`, hash-pins its inline style and script, embeds only the hashes required by the inherited parent policy, and creates it with `sandbox="allow-scripts allow-downloads"` without `allow-same-origin`. The child sends one payload-free readiness signal; the warm shell accepts it only from that frame and enters a terminal lockdown state with an explanation if creation or readiness fails.

This branch is based on the unmerged `p0.5-warm-shell-skeleton` branch. Its PR base must therefore be `p0.5-warm-shell-skeleton`.

## 2. Scope

### In scope

- Deterministic assembly of the cold `srcdoc` document, style, and script
- Cold-realm CSP with hash-pinned inline blocks and `connect-src 'none'`
- Opaque iframe sandboxing with `allow-scripts allow-downloads` and no `allow-same-origin`
- Parent-side readiness validation, timeout, and visible fail-closed lockdown state
- Browser-harness coverage for the sealed frame, blocked `fetch`/XHR/WebSocket, parent DOM isolation, and iframe creation failure
- Roadmap, changelog, and CSP-policy documentation updates

### Deliberately out of scope

- MessageChannel transfer, typed message schema, or secret-bearing messages (P0.7)
- CSP canary, online-state banner, and runtime network neutering (P0.8)
- Capability detection, cryptography, vault storage, and secret fields
- Real-device certification, which remains P0.19

## 4. Acceptance criteria

| Criterion | How satisfied | Test |
|---|---|---|
| `srcdoc` iframe with `sandbox="allow-scripts allow-downloads"` and its own CSP including `connect-src 'none'`. | The build assembles `src/cold/index.html`, hash-pins its inline blocks, embeds the resulting document in `main.js`, and creates the iframe with the exact sandbox token. The child CSP is checked at runtime and the parent CSP includes the child hashes required by restrictive `srcdoc` inheritance. | `test/build.test.js` checks the embedded policy and opaque sandbox; `test:browser` checks the runtime child policy and both inline hashes. |
| `fetch`, XHR, and WebSocket inside the iframe are blocked. | The child policy uses `connect-src 'none'`; per [ADR-0008](../adr/0008-csp-blocked-network-signals.md), browser-specific rejection, error, or close signals are accepted only when the same primitive also produces a matching `connect-src` violation. | `test:browser` exercises all three primitives inside the built cold frame in Chromium and Firefox and requires a blocked result plus that primitive's frame `connect-src` violation. |
| Warm shell cannot read the cold frame's DOM or variables. | The iframe omits `allow-same-origin`, so its `srcdoc` realm has an opaque origin. The harness probes the child DOM, a child global marker, and `contentDocument`; none are readable. | `expectParentCannotReadFrame()` passes in Chromium and Firefox. |
| App fails closed with an explanation if the iframe cannot be established. | Creation and readiness are guarded. A missing `srcdoc`, creation exception, or missing ready signal sets `data-cold-state="failed"`, removes any attached frame, and reveals the lockdown explanation. | The harness deliberately makes iframe creation throw and separately suppresses the ready signal; both paths leave no frame, lock the app, and show the explanation in both engines. |

## 5. Security impact

- Realm boundary: **Yes.** The cold realm is now a sandboxed opaque-origin `srcdoc` frame. No `allow-same-origin` token is present.
- Message schema: **Provisional only.** The child sends `{ type: "cold.ready" }` with no other fields and no secret payload. The parent requires the event source to be the created frame and removes the provisional global listener after readiness. P0.7 must replace this bootstrap signal with the typed MessageChannel handshake and validator.
- CSP: **Yes.** The child policy is hash-pinned and contains `default-src 'none'`, `connect-src 'none'`, `form-action 'none'`, `frame-src 'none'`, `object-src 'none'`, `base-uri 'none'`, and `worker-src blob:`. The parent policy now includes the child hashes because `srcdoc` policies inherit and combine restrictively.
- New `connect-src` hosts: **None.** The warm allowlist is unchanged; the cold policy allows none.
- Runtime neutering/canary: **Not yet.** Those defense-in-depth controls belong to P0.8. This item relies on the tested CSP boundary and fails closed if the realm cannot signal readiness.
- `frame-ancestors`: The shipped local-file meta policy omits this header-only directive because Chromium reports it as ignored when delivered through meta. The sandbox and parent `frame-src` boundary remain active, and the limitation is documented in `docs/02-security/csp-policy.md`.

## 6. Test evidence

### New and changed tests

- `scripts/build.js` now assembles and hash-pins the cold document before embedding it safely into the warm inline script.
- `scripts/run-browser-harness.js` validates the exact sandbox, child CSP hashes, per-primitive cold network blocking, opaque parent boundary, clean boot console, and fail-closed iframe creation and readiness-timeout paths in Chromium and Firefox.
- `test/build.test.js` checks that the cold policy is embedded, hash placeholders are resolved, `connect-src 'none'` is present, `allow-same-origin` is absent, and an extra sandbox token fails the exact-token assertion.
- `test/browser/harness.js` correlates each requested CSP probe with its own `connect-src` violation and probes DOM, child variables, and `contentDocument` isolation.

### Negative tests

- `fetch`, XHR, and WebSocket attempts in the cold frame are blocked in both browser engines, with a matching per-primitive `connect-src` violation.
- Parent access to `iframe.contentWindow.document`, the child marker variable, and `contentDocument` is rejected or absent under the opaque sandbox in both engines.
- Deliberate iframe creation failure and a suppressed-ready timeout each produce a visible lockdown state and no active frame in both engines.
- A negative build fixture adding `allow-top-navigation` fails the exact sandbox-token assertion.
- A temporary eval source fixture makes the build exit non-zero at the forbidden-construct lint gate.
- Existing outer-script tamper and deliberate CSP violation checks continue to pass.

### Not tested

No real iOS Safari, Android Chrome from Files, macOS Safari, Linux Firefox, Tor Browser, or physical-device behavior was available. Header-delivered CSP behavior is also not tested because the product artifact is a local HTML file. Those results are not inferred from the headless runs and remain part of P0.19 or a later deployment-specific verification.

## 8. Assumptions made

> **Assumed:** A payload-free global `cold.ready` signal is acceptable as the bootstrap liveness signal before the P0.7 handshake.
> **Basis:** The parent needs proof that the opaque child script ran, while the architecture assigns the typed MessageChannel and global-handler shutdown to P0.7; the signal carries no secret or public data beyond its type.
> **Not verified on:** Real-device browsers.
> **If wrong:** P0.7 must replace or constrain the signal before any secret-bearing operation is added. No secret operation is implemented on this branch.

> **Assumed:** The parent CSP must include the child inline hashes because `srcdoc` inherits the parent policy.
> **Basis:** The first browser run showed the child style/script being blocked by the outer hash list; adding only the exact child hashes restored the intended restrictive intersection, and the child policy remains independently hash-pinned.
> **Not verified on:** Browsers outside the automated Chromium and Firefox matrix.
> **If wrong:** The child may fail to boot or a browser may interpret inherited policies differently; the runtime readiness timeout fails closed rather than falling back to a single realm.

> **Assumed:** A 1500 ms readiness timeout is long enough for a local `srcdoc` child on supported browsers.
> **Basis:** The child is embedded and has no network dependency; the timeout is short enough to avoid presenting a false-ready shell after a failed boot.
> **Not verified on:** Mobile Safari, Files providers, and slower physical devices.
> **If wrong:** P0.19 should record the platform result and adjust the timeout without weakening the fail-closed state.

> **Assumed:** A readiness timeout must remove a frame that may have started running but never established the boot signal.
> **Basis:** Leaving such a frame attached would violate the terminal-lockdown intent; `setColdRealmFailure()` now removes it before exposing the failure state, and the browser harness covers the suppressed-ready path.
> **Not verified on:** Mobile Safari, Files providers, and slower physical devices.
> **If wrong:** A platform that needs a longer startup window may require a measured timeout adjustment, but it must retain frame removal on failure.

## 9. What to scrutinise

- The JSON escaping in `scripts/build.js`; the embedded document must never terminate the outer inline script or leave an unresolved placeholder.
- The parent `message` source check and removal of the provisional listener; P0.7 must not allow this bootstrap path to carry secrets.
- The exact `sandbox` token and absence of `allow-same-origin` in the built artifact.
- The child CSP and the reason the parent includes only its hash-pinned child blocks.
- Timeout behavior on slow or partially supported `file://` browsers, especially iOS Safari from Files; the automated suppressed-ready fixture now confirms that failure removes the child.
- The per-primitive CSP-violation correlation in the network probe; a browser-specific API error without its matching policy event must fail the harness.
- The documented `frame-ancestors` meta limitation and whether a future packaged/header-delivered artifact can enforce it.

## 10. Self-assessment

- The message path is deliberately only a liveness signal. It is not a protocol and must not be reused for secret or public application data; P0.7 owns the protocol.
- Runtime network neutering and a CSP canary are not present yet; P0.8 remains required before vault operations.
- The browser harness verifies the central automated claim in Chromium and Firefox, but no physical-device claim is made.
- The roadmap's former "throw" wording was resolved by ADR-0008 to test the CSP block itself, while leaving runtime throw stubs to P0.8.
- The outer shell still has no secret fields or vault operations. The Vault route is a placeholder with an established sealed realm above it.
- The `frame-ancestors` limitation is documented rather than hidden; the shipped file uses the controls that can be enforced in a local artifact.
