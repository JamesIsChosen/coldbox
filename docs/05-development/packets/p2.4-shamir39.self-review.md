### Diagnosis and canonical behavior

`readBuildCommitDate()` in `scripts/build.js` invokes:

```text
git log -1 --format=%cI HEAD -- src scripts vendor
```

The query is intentionally path-scoped to the build inputs. In a fresh clone
of the exact committed state, Node successfully spawned Git; the command
returned status 0 and:

```text
2026-08-12T19:26:15-07:00
```

The built HTML contained:

```text
var PROVENANCE_BUILD_DATE = "2026-08-12T19:26:15-07:00";
```

That date-bearing result is the canonical clean-clone behavior:
`c01bfb3946487ef81d2fdd3ca0b1dc537ab437ba02147f7b7678dc1eeaed0e66`,
2,263,833 bytes.

The `08ca146a…` result is the fallback when `spawnSync('git', …)` returns an
error such as `EPERM`. Its HTML contains:

```text
var PROVENANCE_BUILD_DATE = "unknown (no git commit metadata available)";
```

That fallback string is 17 bytes longer than the date-bearing value, exactly
accounting for the 17-byte artifact-size difference. It remains intentional
because the field is informational, but it is not the normal clean-clone
artifact and must not be used for current Bundle Impact claims.
