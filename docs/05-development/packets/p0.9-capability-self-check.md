# PR packet: P0.9 - Capability self-check panel

## 1. Summary

P0.9 adds a boot-time capability panel to the warm shell and a matching capability report in the cold realm. The shared detector checks the required `crypto.getRandomValues` source plus optional WebCrypto SubtleCrypto, WASM, Workers, camera API, and the three documented save paths. The panel reports the warm/cold result for realm capabilities and summarizes the save paths available to the warm shell.

The required randomness check performs a real one-byte `crypto.getRandomValues` call. If it is missing or throws in either realm, the app enters visible full lockdown, refuses vault operations, removes the cold frame, and explains that it never substitutes `Math.random`. There is no randomness fallback.

The source linter treats executable `Math.random()` in `src/capabilities.js` as a forbidden construct. A mutation fixture replaces the real `getRandomValues` call with `Math.random()` and proves both direct capability lint and the build exit non-zero.

This branch is based on the unmerged `p0.8-csp-canary-airgap-guard` branch. Its PR base must therefore be `p0.8-csp-canary-airgap-guard`.

## 2. Scope

### In scope

- Shared capability detector embedded into the warm and cold documents
- Boot-time capability panel with required, optional, and save-path states
- Hard failure for missing or unusable `crypto.getRandomValues` in either realm
- Minimal WASM instantiation probe and an actual blob Worker probe with cleanup and timeout
- Non-permission-requesting camera API presence check
- File System Access, blob-download, and manual-export availability checks without writing a file
- Typed cold readiness capability fields for the new checks
- `worker-src blob:` in the warm and cold CSP policies so the Worker probe is governed explicitly
- Chromium/Firefox normal-panel and missing-randomness browser fixtures
- Protocol/build regression tests, security documentation, roadmap, changelog, packet, and review evidence

### Deliberately out of scope

- Cryptographic known-answer tests, KDF selection, or Argon2id loading (P0.10)
- Requesting camera permission or implementing QR scanning (later feature work)
- Performing save/load operations or claiming that an available API has successfully written a vault (P0.13+)
- Physical Safari, mobile, Tor, and other real-device confirmation, which remains P0.19
- Any merge of this branch or its dependency branches

## 5. Security impact

- Required randomness: The detector calls `crypto.getRandomValues` directly and treats missing, malformed, or throwing behavior as unavailable. The warm shell refuses to continue unless both warm and cold reports are true. The cold realm gates its ready state on the same requirement. No `Math.random` fallback exists.
- Realm boundary: Preserved. The cold frame remains `sandbox="allow-scripts allow-downloads"` without `allow-same-origin`; the warm shell receives only typed capability booleans through the existing private channel.
- CSP: The warm and cold policies explicitly include `worker-src blob:` for the actual Worker probe and future worker-backed work. The warm `connect-src` allowlist and cold `connect-src 'none'` remain unchanged; no new network host was added.
- WebCrypto: `crypto.subtle` is reported as an optional capability only. P0.9 does not treat its presence as proof of cryptographic correctness or select a crypto path.
- WASM: The probe instantiates a fixed minimal module and does not execute application code. The existing `'wasm-unsafe-eval'` token remains required for the policy.
- Camera: Only API presence is checked. Boot never calls `getUserMedia`, so the panel does not request permission.
- Saving: The checks detect API affordances without opening a picker, downloading a file, or exposing vault bytes. Actual save integrity and the complete manual flow remain later roadmap work.
- Failure mode: A required-capability failure is visible and terminal for the session. The app does not silently degrade to an insecure single-realm or weak-randomness mode.

## 6. Test evidence

### New and changed tests

- `src/capabilities.js` implements the shared detector, the required randomness call, the minimal WASM probe, the blob Worker round trip, camera API check, and save-path checks.
- `src/main.js` renders the panel, combines warm and cold reports, applies optional warnings, and enters full lockdown on a required randomness failure.
- `src/cold/main.js` detects capabilities inside the opaque cold realm, reports typed booleans, and withholds `cold-state="ready"` when randomness is unavailable.
- `src/protocol.js` preserves the new typed capability fields while stripping unknown fields.
- `scripts/build.js` embeds the detector into both realms and rejects unresolved placeholders.
- `src/index.html` and `src/styles.css` add the accessible panel, row states, responsive layout, and visible failure copy.
- `test/build.test.js` asserts both-realm capability markers, required randomness, and explicit Worker CSP support.
- `test/build.test.js` mutates the required randomness call to `Math.random()` and asserts both capability lint and the build reject it with a non-zero result.
- `test/protocol.test.js` covers the new capability fields and their canonical typed schema.
- `scripts/run-browser-harness.js` covers normal capability reporting and a temporary missing-randomness fixture in Chromium and Firefox.

### Negative tests

- A missing `getRandomValues` fixture enters full lockdown and refuses vault operations in both browser engines.
- A deliberate `getRandomValues` to `Math.random()` mutation is rejected by the capability-specific lint guard and by the build before an artifact is emitted.
- The negative fixture asserts the visible explanation includes `never substitutes Math.random`.
- Existing stripped-CSP, cold-frame creation failure, CSP violation, byte-tampering, runtime network-primitive, routing, responsive, and opaque-frame checks continue to pass.
- The deliberate forbidden-construct fixture remains a required non-zero build failure.
- The dependency-free build remains byte-identical to the normal build.

### Not tested

No real iOS Safari, Android Chrome from Files, macOS Safari, macOS Chrome, Linux Firefox, or Tor Browser was available. Their capability results are not inferred from headless Chromium or Firefox and remain part of P0.19.

## 8. Assumptions made

> **Assumed:** A one-byte `crypto.getRandomValues` call is a sufficient boot-time availability check.
> **Basis:** P0.9 requires the API to be present and usable; known-answer cryptographic validation belongs to P0.10, while an actual call catches missing or throwing implementations.
> **Not verified on:** Physical browsers.
> **If wrong:** The affected platform must remain locked down until a platform-specific detector or an explicit security decision is recorded.

> **Assumed:** A blob Worker round trip is the right capability test for the Worker path.
> **Basis:** Presence alone does not prove that a Worker can be created under the shipped CSP and local-file delivery model; the probe creates, messages, times out, terminates, and revokes its object URL.
> **Not verified on:** iOS Safari and other physical platforms.
> **If wrong:** The device matrix must record the platform as unavailable and the later worker-backed feature must use its documented main-thread fallback.

> **Assumed:** Camera and save-path probes should be non-invasive at boot.
> **Basis:** The panel reports capability affordances without requesting permission or writing data; actual workflows own permission and I/O.
> **Not verified on:** Physical browsers and browser privacy modes.
> **If wrong:** The affected workflow must surface its own runtime failure and preserve the manual save path where available.

## 9. What to scrutinise

- The required randomness check must remain a direct `crypto.getRandomValues` call in both realms; no fallback, cached value, or truthy property check is sufficient.
- The warm shell must not accept a cold ready message whose `randomValues` field is false or absent.
- A missing-randomness path must visibly explain the reason, set full lockdown and refused vault operations, and remove the cold frame rather than leaving a partially trusted app active.
- Optional `crypto.subtle`, WASM, Workers, camera, and save-path results must remain informational and must not be treated as proof of cryptographic correctness or completed I/O.
- The Worker probe requires an explicit `worker-src blob:` policy and must clean up its Worker, timer, and object URL.
- The warm network allowlist and cold `connect-src 'none'` policy must not gain a host as part of capability detection.
- No physical Safari/mobile result may be presented as verified; P0.19 owns those claims.

## 10. Self-assessment

- P0.9 establishes the required boot gate and an honest capability display, but it does not implement cryptography, saving, camera workflows, or KDF selection.
- API availability is not the same as feature correctness. P0.10 and later items must perform known-answer tests and end-to-end workflow checks.
- The Worker probe is intentionally bounded at 500 ms; a platform that cannot complete it is reported unavailable rather than blocking boot indefinitely.
- `crypto.subtle` can exist in one realm and not the other; the panel reports the distinction, while only `randomValues` is a hard requirement at this stage.
- The automated matrix covers Chromium and Firefox only. Real-device behavior remains intentionally unclaimed.
