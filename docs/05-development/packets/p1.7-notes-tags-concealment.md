# PR packet: P1.7 Notes, tags, and concealment levels

## 1. Summary

P1.7 adds public Markdown notes, canonical shared tags, registry search,
reversible hidden records, persisted privacy blur, and a cold-only secret-note
editor. Public protocol validation rejects secret note visibility and
secret-shaped public content. Secret-note plaintext, search, masking, and
timed reveal stay inside the encrypted cold compartment. The roadmap marker
remains `[~]` pending independent review.

Roadmap: [P1.7 Notes, tags, and concealment levels](../ROADMAP.md).

## 2. Scope

In scope:

- Public Note records with bounded Markdown bodies, links, canonical tags, and soft-hide behavior.
- Shared tags and search across the P1.6 public registry collections and notes.
- Warm-shell privacy blur persisted in local storage, with no secret data involved.
- Session-scoped hidden-record reveal whose phrase is re-entered and checked only in the cold realm.
- Cold-only secret-note storage, cold-local search, masking, timed reveal, and lock/panic DOM cleanup.
- Explicit hidden-state reversal on edits (`hidden: false`) instead of merge-preserving stale concealment.
- Browser acceptance for public note/tag CRUD, wrong/correct concealment re-authentication, and cold-local secret notes in Chromium and Firefox.
- Typed protocol messages, cold-session secret-compartment mutation, tests, help content, ADR-0032, CHANGELOG, and the `[~]` roadmap state.

Deliberately out of scope:

- Device records (P1.8), verification workflows (P1.9/P1.11), QR generation (P1.10), clipboard verification (P1.12), and clipboard canaries (P1.13).
- Secret notes in the warm Registry form or any warm access to the secret compartment.
- Duress/decoy compartments, downloadable vault QR, network-backed note search, or BIP-329 export.

## 5. Security impact

Yes. This item extends the message schema, the cold vault session API, and
warm/cold UI state. The cold realm CSP is unchanged and still has
`connect-src 'none'`; no new network host, runtime dependency, or external URL
was added.

New typed messages are intentionally content-free or boolean-only:

- Warm to cold `concealment.reveal` accepts only `{}`.
- Cold to warm `concealment.revealed` returns only `{ revealed: boolean }`.
- Cold to warm `secretData.updated` returns only `{ dirty: true }` after a cold-local encrypted note mutation.
- The existing `publicData.replace` channel now accepts the bounded public `notes` schema; `visibility: secret`, secret keys, unknown text carriers, and recognizable secret-shaped values are rejected before crossing.

The re-authentication phrase is read by the cold frame through
`vaultLayer.openSession`; only the boolean result crosses back. Online sessions
return `null` for secret data and reject secret replacement. Lock/panic teardown
clears the cold secret-note form, rendered note cards, reveal timers, session
object, and encrypted byte copies. If this boundary were wrong, a warm
compromise could read secret-note plaintext or a phrase; the tests assert the
absence of secret-bearing message fields and online secret access.

The warm privacy-blur preference uses warm `localStorage` only and contains no
vault or note plaintext. It is a shoulder-surfing aid, not cryptographic
protection against the operating system, extensions, or screen capture.

The cold secret-note control uses an explicit button action rather than native
form submission. The iframe sandbox intentionally omits `allow-forms`; this
keeps native form navigation unavailable while the button handler still saves
only through the cold session API.

## 8. Assumptions made

- The existing encrypted secret compartment is the authoritative home for `visibility: secret` notes. An offline new vault is initialized with `{ notes: [] }` so its cold editor is available immediately; an online-created vault remains public-only.
- Public Markdown bodies are stored and displayed as escaped text, not interpreted as HTML. This keeps the UI safe while retaining the user's Markdown source for later export/rendering work.
- Hidden records remain soft-hidden rather than deleted, consistent with the existing Registry tombstone model. The current session flag is cleared on lock, panic hide, and every vault open.
- A user can still type sensitive prose into a field explicitly labeled public; no regex can prove arbitrary prose safe. The UI, help content, public-only schema, and secret-shaped rejection make the compartment choice explicit rather than pretending classification is perfect.

## 9. What to scrutinise

- The `cleanNoteRecord`/`cleanPublicCompartment` path in `src/protocol.js`: future public collections or note fields must not accidentally become free-form secret carriers.
- `completeHiddenRecordReveal` in `src/cold/main.js`: phrase handling, stale encrypted-byte behavior, and the boolean-only acknowledgement must remain cold-local and fail closed on channel or mode changes.
- `getSecretData`/`replaceSecretData` in `src/cold/vault.js`: the session must preserve the existing secret compartment length, re-encrypt it with a fresh nonce on save, and never expose it through `vault.open` online or a postMessage.
- Lock/panic cleanup in both realms and the warm `data-privacy-sensitive` styling. The browser harness covers the inherited lock/airgap paths and the new note-specific workflows.
- The explicit secret-note button path and the unchanged iframe sandbox: do not add `allow-forms` merely to make native form submission work.

## 10. Self-assessment

The remediation pass exposed three concrete issues before this final gate: a UI
string containing the forbidden word `require` broke deterministic lint/build
checks; the initial cold lock path hid secret-note UI without clearing its DOM
values; and an offline-created vault initialized an empty secret object, so the
cold note panel did not appear. Those fixes are preserved in the branch
history. The cold iframe also cannot dispatch native form submission without
`allow-forms`, so the final control uses an explicit button handler and keeps
the sandbox restriction intact.

The cold secret-note editor appends, searches, masks, reveals, and clears notes
but does not yet provide separate edit/delete controls. Native `.cbx`
persistence, public note CRUD, and the roadmap's concealment boundary are
complete; richer secret-note lifecycle controls remain a future cold-local
extension.

No real seed phrase, private key, keyfile, or vault file was created or committed.
