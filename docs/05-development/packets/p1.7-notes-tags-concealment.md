# PR packet: P1.7 Notes, tags, and concealment levels

## 1. Summary

P1.7 adds public Markdown notes, canonical shared tags, registry search, reversible hidden records, persisted privacy blur, and a cold-only secret-note editor. The public protocol rejects secret note visibility and secret-shaped public content; secret-note plaintext stays inside the encrypted cold compartment. The roadmap marker remains `[~]` pending independent review.

Roadmap: [P1.7 Notes, tags, and concealment levels](../ROADMAP.md).

## 2. Scope

In scope:

- Public Note records with bounded Markdown bodies, links, canonical tags, and soft-hide behavior.
- Shared tags and search across the P1.6 public registry collections and notes.
- Warm-shell privacy blur persisted in local storage, with no secret data involved.
- Session-scoped hidden-record reveal whose phrase is re-entered and checked only in the cold realm.
- Cold-only secret-note storage, cold-local search, masking, timed reveal, and lock/panic DOM cleanup.
- Typed protocol messages, cold-session secret-compartment mutation, tests, help content, ADR-0032, CHANGELOG, and the `[~]` roadmap state.

Deliberately out of scope:

- Device records (P1.8), verification workflows (P1.9/P1.11), QR generation (P1.10), clipboard verification (P1.12), and clipboard canaries (P1.13).
- Secret notes in the warm Registry form or any warm access to the secret compartment.
- Duress/decoy compartments, downloadable vault QR, network-backed note search, or BIP-329 export.

## 5. Security impact

Yes. This item extends the message schema, the cold vault session API, and warm/cold UI state. The cold realm CSP is unchanged and still has `connect-src 'none'`; no new network host, runtime dependency, or external URL was added.

New typed messages are intentionally content-free or boolean-only:

- Warm → cold `concealment.reveal` accepts only `{}`.
- Cold → warm `concealment.revealed` returns only `{ revealed: boolean }`.
- Cold → warm `secretData.updated` returns only `{ dirty: true }` after a cold-local encrypted note mutation.
- The existing `publicData.replace` channel now accepts the bounded public `notes` schema; `visibility: secret`, secret keys, unknown text carriers, and recognizable secret-shaped values are rejected before crossing.

The re-authentication phrase is read by the cold frame through `vaultLayer.openSession`; only the boolean result crosses back. Online sessions return `null` for secret data and reject secret replacement. Lock/panic teardown clears the cold secret-note form, rendered note cards, reveal timers, session object, and encrypted byte copies. If this boundary were wrong, a warm compromise could read secret-note plaintext or a phrase; the tests specifically assert the absence of secret-bearing message fields and online secret access.

The warm privacy-blur preference uses warm `localStorage` only and contains no vault or note plaintext. It is a shoulder-surfing aid, not cryptographic protection against the operating system, extensions, or screen capture.

## 6. Test evidence

New tests cover:

- Protocol message whitelist additions, unknown-field stripping, public-only note visibility, bounded Markdown/tags/links, and secret-shaped content rejection.
- Registry note CRUD, relationship checks, canonical shared tags, search, soft-hide, clone isolation, and secure UUID failure behavior.
- Privacy-blur persistence, timed reveal, and panic-hide state cleanup.
- Offline secret-compartment note mutation, save/reopen persistence, public projection isolation, and online-session refusal.

No new cryptographic primitive or derivation vector was introduced. ## 8. Assumptions made

- The existing encrypted secret compartment is the authoritative home for `visibility: secret` notes; an offline new vault is initialized with an empty secret object so its cold editor is available, while an online-created vault remains public-only.
- Public Markdown bodies are stored and displayed as escaped text, not interpreted as HTML. This keeps the UI safe while retaining the user's Markdown source for later export/rendering work.
- Hidden records remain soft-hidden rather than deleted, consistent with the existing Registry tombstone model. The current session flag is cleared on lock, panic hide, and every vault open.
- A user can still type sensitive prose into a field explicitly labeled public; no regex can prove arbitrary prose safe. The UI, help content, public-only schema, and secret-shaped rejection make the compartment choice explicit rather than pretending classification is perfect.

## 9. What to scrutinise

- The `cleanNoteRecord`/`cleanPublicCompartment` path in `src/protocol.js`: future public collections or note fields must not accidentally become free-form secret carriers.
- `completeHiddenRecordReveal` in `src/cold/main.js`: phrase handling, stale encrypted-byte behavior, and the boolean-only acknowledgement must remain cold-local and fail closed on channel or mode changes.
- `getSecretData`/`replaceSecretData` in `src/cold/vault.js`: the session must preserve the existing secret compartment length, re-encrypt it with a fresh nonce on save, and never expose it through `vault.open` online or a postMessage.
- Lock/panic cleanup in both realms and the warm `data-privacy-sensitive` styling. The browser harness covers the inherited lock/airgap paths; the new note-specific workflow remains primarily covered by unit/projection tests.

## 10. Self-assessment

The first P1.7 review pass exposed two issues before the final gate: a UI string containing the forbidden word `require` blocked deterministic builds, and the initial cold lock path hid secret-note UI without clearing its DOM values. They were fixed in `ccf82ac` and `249e924`; the final re-review passed all checks. The current cold secret-note editor appends, searches, and lists notes but does not yet provide separate edit/delete controls; native `.cbx` persistence, public note CRUD, and the roadmap's concealment boundary are complete, while richer secret-note lifecycle controls remain a future cold-local extension.

No real seed phrase, private key, keyfile, or vault file was created or committed.
