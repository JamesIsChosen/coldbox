## 4. Findings

### F1 — Criterion 3 is verified against a fixture, not against the built artifact

**Severity:** blocking
**Location:** `scripts/run-browser-harness.js:56-67` (`createTamperedFixture`), `scripts/run-browser-harness.js:112-125` (`verifyTamperFixture`), `test/build.test.js:114-146`, packet §1/§4/§6

**Observed:** The criterion is about `build/coldbox.html`. Neither piece of evidence touches it.

*Browser side.* `createTamperedFixture()` reads `test/browser/fixtures/tamper.html` — a hand-written P0.3a fixture whose `script-src 'sha256-gZ8Qt…'` is a hardcoded literal — appends a space to its inline script, and asserts the browser refuses it. `buildPath` appears three times in the harness (lines 16, 79, 164) and never in the tamper path. The harness never tampers with the built file.

*Node side.* The new test computes `cspHash(alteredScript)`, asserts it differs from `cspHash(scripts[0])`, and asserts the altered hash is absent from `script-src`. That is a restatement of SHA-256's collision resistance. No browser is involved, and no artifact is modified on disk.

The consequence is measurable: **every assertion in `npm run test:browser` passes identically on `main`, where `src/index.html` contains no CSP meta tag at all** (`git show main:src/index.html | grep -c Content-Security-Policy` → `0`). With no policy present there are no violations to observe, so `verifyBuiltFile` is satisfied trivially, and the three fixture-based checks are unaffected by this PR. The harness provides **zero** coverage of the hash-pinning this PR adds. Reverting the entire change would not turn it red.

Packet §8 assumes "the P0.3a harness is the agent-verifiable acceptance mechanism for P0.4." The assumption is reasonable; what the harness actually asserts does not discharge it.

**Expected:** A browser assertion that the *built* artifact's own emitted hash is what refuses the tampered script.

**Required action:** Add a harness step that copies `build/coldbox.html` to a temporary path, flips one byte inside the inline `<script>` body (leaving the CSP meta untouched), loads it over `file://` in both engines, and asserts both directions:

- a `script-src` violation fires, and
- the script's observable effect is absent — `#app` must not carry `data-build-state="skeleton"`.

Assert the positive control on the untampered build too: `#app[data-build-state="skeleton"]` must be present. Without it, "no CSP violations" and "nothing ran" are indistinguishable at the harness level.

### F2 — The build's unresolved-placeholder guard now fails open

**Severity:** blocking
**Location:** `scripts/build.js:56-60`

**Observed:** `assemble()` previously rejected any residual token:

```js
if (document.includes('__COLDBOX_')) {
  throw new Error('Unresolved source placeholder in assembled document');
}
```

It now checks a two-name whitelist, and nothing re-checks the document after `injectCspHashes()`. The catch-all was presumably narrowed because the CSP hash placeholders legitimately survive `assemble()` — but the fix moved the guard's coverage down rather than moving the guard later.

Demonstrated on a fresh copy, replacing `<title>Coldbox</title>` with `<title>__COLDBOX_TYPO__</title>`:

```
$ node scripts/build.js
exit=0
$ grep -o '__COLDBOX_TYPO__' build/coldbox.html
__COLDBOX_TYPO__
```

The build succeeds and ships the literal token. On `main` the same input aborts. This is a fail-open regression in a build-time guard, in a project whose stated principle is that failure modes fail closed — and it landed in a PR about tightening the build.

The two hash placeholders themselves are still protected, because `injectOnce` throws on `occurrences !== 1` (verified above, exit 1). The exposure is any *other* placeholder: a typo, or one added by a later item whose author forgets to extend the whitelist. P0.5 adds the warm shell and P0.6 the cold realm srcdoc, both of which will add placeholders.

**Expected:** Non-zero exit and no artifact, as on `main`.

**Required action:** Run the catch-all `__COLDBOX_` check on the final document after `injectCspHashes()` — not inside `assemble()` — and keep it as a regex over the whole artifact rather than a name list. Add a test asserting a stray placeholder produces a non-zero exit and no `build/` output.

### F3 — Packet and CHANGELOG claim browser verification the code does not perform

**Severity:** advisory
**Location:** `docs/05-development/packets/p0.4-csp-hash-pinning.md` §1, §4 row 3, §6; `CHANGELOG.md` "Added — P0.4"

**Observed:**

- Packet §1: "The P0.3a harness verifies the built file over `file://` in Chromium and Firefox, **including the browser refusal of a tampered script**." The refusal is observed on a fixture, not on the built file.
- Packet §4 row 3: "The tamper fixture adds one byte to the inline script without changing **the emitted hash**." The fixture's hash is a hardcoded literal; the build emits nothing into it.
- Packet §6: "One-byte **post-build** script tampering" and "Browser observation of untampered execution and tampered rejection" listed as new P0.4 coverage. Both predate this PR.
- CHANGELOG: "Regression tests for multiple inline blocks and **post-build script tampering**." The tampering test operates on an in-memory string and never writes a modified artifact.

Per [doc-hygiene.md](../doc-hygiene.md), a document that makes a reader confident and wrong is a defect. These statements would lead a future reader — or a future reviewer — to believe a check exists that does not.

**Expected:** Claims that match what the code asserts.

**Required action:** Once F1 is fixed, the packet and CHANGELOG statements become true and need only the fixture-vs-artifact distinction made explicit. If F1 is deferred, the claims must be withdrawn instead.

## 5. Verdict rationale

The implementation itself is good. The hashing is correct byte-for-byte, the policy is a faithful copy of the documented warm-shell policy with nothing added, missing placeholders and missing inline blocks both fail closed with non-zero exits, and the build reproduced to the same digest across two operating systems, four environments, a Unicode path, and a Turkish locale. Criterion 1 is met and criterion 2 is met.

It fails on criterion 3 and on a regression. The tamper evidence is a P0.3a fixture that would pass unchanged if this PR were reverted — the harness never touches the built artifact's own hash, so the central claim of the item is asserted rather than tested, and the accompanying Node test only demonstrates that SHA-256 is a hash function. Separately, narrowing the unresolved-placeholder guard to a two-name whitelist turned a fail-closed build check into a fail-open one, which I reproduced directly.

**This becomes a PASS when:** the harness tampers with a copy of `build/coldbox.html` itself and both engines report the pinned script refused *and* not executed, with a positive control on the untampered build; the `__COLDBOX_` catch-all runs on the final document with a test covering it; and the packet, CHANGELOG, and roadmap status match what the code then verifies.

I did not merge. Per the protocol, findings go back to the author.
