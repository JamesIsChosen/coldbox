## Acceptance criteria, checked verbatim against the roadmap

> **Accept:** RFC 9106 Argon2 vectors and NIST AES-GCM vectors pass on both paths; **vault details display which KDF is actually active**, so a silent PBKDF2 fallback is impossible.

### Vectors are genuinely independent — recomputed, not trusted

`AGENTS.md` §3 requires independent vectors, so the constants in `src/cold/crypto.js` were checked against primary sources rather than accepted.

**AES-GCM** (`crypto.js:173`, `:193`) — recomputed from scratch with OpenSSL via Node, AES-128-GCM, all-zero key/IV/plaintext:

```
independently computed: 0388dace60b6a392f328c2b971b2fe78ab6e47d42cec13bdf53a67b21257bddf
constant in crypto.js : 0388dace60b6a392f328c2b971b2fe78ab6e47d42cec13bdf53a67b21257bddf
MATCH
```

**Argon2id** (`crypto.js:223`) — compared against RFC 9106 §5.3, fetched from `rfc-editor.org` during this review. The RFC's tag is `0d 64 0d f5 8d 78 76 6c 08 c0 37 a3 4a 8b 53 c9 d0 1e f0 45 2d 75 b6 5e b5 25 20 e9 6b 01 e6 59`, which concatenates to exactly the constant in the source. The inputs at `crypto.js:219-232` also match the RFC vector exactly: password 32×`0x01`, salt 16×`0x02`, secret 8×`0x03`, associated data 12×`0x04`, t=3, m=32 KiB, p=4, tag length 32, type Argon2id.

Both known-answer tests therefore use published third-party vectors with correct parameters. Criterion satisfied.

### The KAT is a runtime gate, not only a test

An initial read of `test/crypto.test.js:52` suggested a weakness — the test asserts `nobleCiphertext` equals `webCryptoCiphertext`, which alone would be cross-implementation agreement rather than a known-answer test. Following `selfTest()` into `crypto.js` resolves it: the hardcoded expected values are compared there, and the test asserts `report.nobleAesGcm`, `report.webCrypto.passed`, and `report.argon2id.passed`. Placing the KAT in the shipped self-test rather than only in the test suite is stronger, because it gates the running application and not just CI.

`test/crypto.test.js:60` proves the gate is affirmative rather than assumed:

```js
await assert.rejects(
  layer.aesGcm('encrypt', key, nonce, plaintext, aad, 'webcrypto'),
  /known-answer test passes/
);
```

WebCrypto refuses to operate until its KAT has passed. This is the "WebCrypto used only after an affirmative known-answer test" requirement, demonstrated by a negative test rather than asserted.

### Silent PBKDF2 fallback is impossible

`test/crypto.test.js:77` constructs a context with Argon2 removed and asserts `report.kdf.id === 'pbkdf2-sha512-fallback'` with a label matching `/PBKDF2-HMAC-SHA512/`, then confirms `getKdfDetails().id` still reports the fallback after a real derivation. The active KDF surfaces in both realms — `cold-kdf-active` and `data-kdf-active` in `src/cold/index.html:19,21`, and `capability-crypto-summary` propagated through `src/main.js:242-243,665-668`. A degraded KDF is therefore visible, not silent. Criterion satisfied.

### Randomness

No executable `Math.random` exists anywhere under `src/`. The six matches are all refusal *copy* stating that Coldbox never substitutes it. `crypto.getRandomValues` is the only randomness source in `crypto.js`.

## What this review could NOT verify

Stated plainly, because a reader should not infer more coverage than exists.

- **Upstream vendor re-download.** `npm run verify-vendor` without `--offline` failed with `fetch failed` — the review environment cannot reach the npm registry for tarball bytes. Only the offline half (local SHA-256 against the manifest) was exercised. Comparing the seven vendored tarballs against upstream releases remains unperformed **by this reviewer**; the packet reports the author's environment did complete it.
- **Browser harness.** Playwright browsers are not installed here, so `npm run test:browser` was not run. The Chromium/Firefox results, including the rendered `argon2id-standard` KDF status, stand on the author's evidence and are not independently confirmed.
- **Node version.** Verified under Node v22.22.3 against the pinned v24.16.0. The artifact hash was byte-identical regardless, which is itself mild evidence of build determinism across major versions.
- **Physical devices.** Out of scope; P0.19 owns that matrix.

None of these is a finding against the author. They are limits of this environment, and each is disclosed rather than papered over.

## Verdict rationale

Both acceptance criteria are met as written, not as reinterpreted. The cryptographic vectors are published third-party values and were re-derived here rather than trusted. The WebCrypto path is gated by an affirmative known-answer test proven by a negative assertion. A degraded KDF is visible in both realms. The build is deterministic across path, locale, and timezone, and fails closed on a corrupted vendor artifact with a non-zero exit.

No finding of any severity was identified.
