# PR packet - P1.9 Verification workflows (remediation)

**Status:** SOFTWARE AND HARDWARE GATES PASS; READY FOR INDEPENDENT
REVIEW.

This packet replaces the stale stopped-round evidence for the P1.9 branch. It
does not edit the historical stacked review. The software remediation and the
human hardware validation are complete; the roadmap marker remains `[~]`
because independent review is still required.

## 1. Summary

P1.9 now has a cold-local Verify Bench that consumes the current public
identity from Seed Forge. Seed Forge is the only mnemonic/passphrase entry
surface. Verify Bench displays the selected network, script family, account
path, account xpub, and bounded receive/change ranges for all four Bitcoin
families, then compares independently entered public device or backup values.

The four public comparison panels are device fingerprint, receive address,
account xpub, and metal backup. The fifth roadmap check, passphrase
verification, is performed by selecting and confirming the exact passphrase in
Seed Forge and comparing the resulting public fingerprint or other public
identity; there is no duplicate passphrase shell.

Remediated findings:

- F9: this packet has no blank line at EOF; the final stacked diff passes
  `git diff --check`.
- F10: the browser harness opens every collapsed workflow before interacting
  with it and checks attached/reset state after lock rather than requiring a
  collapsed status to be visible.
- F11: Seed Forge owns passphrase semantics, including leading, trailing, and
  internal spaces; unit tests prove distinct passphrases derive distinct
  identities.
- F12: external fingerprints, extended keys, Base58 addresses, and Bech32
  addresses are strict public inputs with canonical encoding, checksum,
  network, witness-version, and program-length validation. Mixed-case Bech32
  is rejected.
- F15: Verify Bench has an explicit **Use current Seed Forge wallet** handoff,
  displays the active public identity and all four family xpubs, and clears
  the linked identity when Seed Forge changes, the network changes, or the
  cold session tears down.
- F16: the standalone BIP-39 passphrase panel and duplicate mnemonic/
  passphrase controls are removed.

F13 is now recorded as complete for the human validation gate. A SeedSigner at
firmware `0.8.0` was used from a Windows PC in Microsoft Edge (exact Edge
version not recorded). Coldbox was loaded from the local `file://` build with
Wi-Fi and Ethernet physically disconnected. A throwaway seed generated solely
for this test was used; fingerprint, receive address, xpub, metal-backup
fingerprint, and passphrase-derived identity all matched. No production seed
was used or committed. No hardware transport, screen-reading, or authenticity
claim was added.

## 2. Scope

In scope:

- Cold-only public identity derivation from the currently generated or
  validated Seed Forge wallet.
- Four public comparison panels plus passphrase verification through the
  authoritative Seed Forge state.
- Strict validation of external public fingerprints, xpubs, Base58 addresses,
  and Bech32/Bech32m addresses.
- Public-only UI rendering, explicit identity invalidation, lock/panic
  teardown, and external-value clearing.
- Chromium and Firefox `file://` coverage, including collapsed `<details>`
  interaction, independent external inputs, mixed-case and invalid-public
  negatives, duplicate-secret-surface absence, and lock teardown.
- Updated guide, ADR-0034, changelog, roadmap state, tests, and this packet.

Deliberately out of scope:

- WebHID, WebUSB, vendor transport, signing, or device authenticity.
- P1.11 address verification state, P1.12 clipboard round trips, and P1.13
  clipboard volatility.
- Marking P1.9 `[x]`; the marker remains `[~]` for independent review.
- Mobile-browser, Safari, Tor Browser, Android Files, or iOS local-execution
  validation beyond the recorded Windows Edge hardware run.

## 6. Findings addressed

### F9 - packet EOF

The stale packet's blank EOF was removed. The final stacked diff is checked by
`git diff --check p1.8-device-registry...HEAD` and produces no output.

### F10 - collapsed details and teardown

`verifyVerificationWorkflows()` now opens each workflow's `<details>` element
before filling or clicking it. After the shared Escape teardown it waits for
attached idle state, confirms the linked wallet is empty and the external
fields are cleared, and confirms all four comparison buttons are disabled.
It no longer asks a collapsed status element to be visible. Chromium and
Firefox each execute and pass these assertions.

### F11 - passphrase semantics and duplicate secret APIs

The passphrase and mnemonic remain in Seed Forge, whose exact passphrase value
is used without trimming or normalization beyond the BIP-39 implementation's
defined semantics. The focused tests prove that `TREZOR`, ` TREZOR`,
`TREZOR `, and `T REZOR` produce distinct fingerprints. The Verify Bench
source and DOM contain no duplicate mnemonic/passphrase workflow API.

### F12 - strict public comparisons

Fingerprint input is printable ASCII and exactly eight hexadecimal characters.
Extended-key input is printable canonical Base58 text and is decoded through
the existing Bitcoin derivation validator. Address input is decoded and
validated against the selected network and script family, including Base58
version/payload length and Bech32/Bech32m checksum, witness version, and
program length. Fullwidth compatibility text, whitespace, invalid extended
keys, mixed-case Bech32, and bad checksums are negative-tested.

### F13 - real hardware gate

The human-required gate is now complete. A throwaway generated test seed was
used with a SeedSigner at firmware `0.8.0`. On a Windows PC, Coldbox ran from
the local `file://` build in Microsoft Edge with Wi-Fi and Ethernet physically
disconnected. Fingerprint, receive address, xpub, backup fingerprint, and
passphrase-derived identity all matched. The exact Edge version was not
recorded; this is the only declared hardware-evidence gap. No secret or
production seed was committed.

### F15 - active Seed Forge wallet handoff

The user explicitly chooses **Use current Seed Forge wallet** after generating
or validating a phrase. Verify Bench displays the source, master fingerprint,
selected account path, selected xpub, receive/change ranges, and all four
family xpubs. The linked object contains only public values. Seed Forge
replacement, invalid derivation, network changes, lock, panic, and teardown
clear the link and public comparison state. Chromium and Firefox cover the
handoff, public display, independent inputs, replacement/teardown path, and
lock cleanup.

### F16 - no standalone passphrase shell

The old passphrase `<details>` panel and all duplicate mnemonic/passphrase
inputs were removed. The browser harness asserts that the Verify Bench has no
passphrase panel and no mnemonic/passphrase inputs. Passphrase identity
differences remain covered through Seed Forge's independent unit tests.

## 7. Security impact

- The change remains cold-local and adds no message type or warm/cold payload.
- `verification.js` derives from Seed Forge's 64-byte seed inside the cold
  realm and returns only public identity and verdict fields. The linked UI
  object stores no mnemonic, passphrase, private key, or xprv.
- External device and backup fields are public-only. Strict parsing fails
  closed before comparison when a canonical encoding or checksum cannot be
  established.
- The cold `connect-src 'none'` policy and existing airgap/zeroization paths
  remain unchanged and are covered by the final browser harness.
- No hardware transport or authenticity claim is made. A manual match still
  requires reading the device's own screen and checking the physical setup.

## 8. Assumptions and gaps

- Seed Forge remains the authoritative location for mnemonic language and
  passphrase selection; Verify Bench does not duplicate either control.
- The current workflow exposes Bitcoin account 0 and five receive plus five
  change addresses per family, as bounded public verification ranges. Future
  account/range expansion is outside P1.9.
- The automated desktop matrix is Windows Chromium and Firefox over `file://`.
  macOS Safari/Chrome, Linux Firefox, Android Chrome from Files, Tor Browser,
  and the iOS local-execution target were not tested.
- The recorded hardware validation used a throwaway generated seed; it does
  not establish device authenticity for any production wallet.
- Exact Microsoft Edge version was not recorded.
- P1.12 owns later clipboard authority and registry-linked address state;
  this item only compares manually entered public values in the cold realm.

## 9. What to scrutinise hardest

1. The exact Seed Forge-to-Verify Bench invalidation paths: replacement,
   network change, lock, panic, and cold-health teardown must never leave an
   old public identity usable.
2. The assembled cold script, not only the source module, must keep all secret
   inputs out of the warm realm and message channel.
3. The extended-key and Bech32 validators must continue to reject malformed or
   ambiguous external text rather than silently normalize it.
4. The physical device-screen comparison remains manual and is not evidence
   of device authenticity; independently verify the recorded SeedSigner
   evidence.
