# PR packet: P0.3a - Headless browser harness

## 1. Summary

This packet covers [P0.3a in the roadmap](../ROADMAP.md): the Playwright development harness that verifies the built HTML over `file://` in Chromium and Firefox. It adds reusable assertions for browser-enforced CSP reporting, hash-tampered script rejection, frame isolation, blocked network primitives, visible elements, and viewport sizes. It also marks only P0.3a complete; P0.4 remains the next item.

## 2. Scope

In scope:

- Pin Playwright 1.62.1 under `devDependencies` and add `npm run test:browser`.
- Build the artifact before browser checks and install missing Playwright Chromium/Firefox binaries on first test use.
- Add the reusable assertion module at `test/browser/harness.js`.
- Add isolated CSP, tamper, and opaque-frame fixtures.
- Add a regression test proving a failed harness check returns exit code 1.
- Update the roadmap, testing guidance, dependency record, and changelog.

Out of scope:

- CSP hash-pinning in the product build (P0.4).
- The production cold realm, message channel, runtime airgap guard, or any vault/crypto feature.
- CI workflow changes (P0.18).
- Real-device testing (P0.19).

## 5. Security impact

The product's realm boundary, message schema, CSP policy, vault format, derivation, and randomness are not changed. The harness observes those properties for later roadmap items but does not create or weaken them.

The test-only frame fixture intentionally uses `https://coldbox.invalid` as a network target and replaces the three primitives with throwing stubs. It is outside `src/` and cannot enter the built artifact. Playwright's browser download is development setup only; the application has no runtime dependency or network path added.

## 6. Test evidence

New tests and fixtures:

- `test/browser/harness.js` captures `securitypolicyviolation` events before page scripts run and provides the eight roadmap assertion surfaces. CSP `script-src-elem`/`script-src-attr` reports are normalized to their policy directive names.
- `test/browser/fixtures/csp-violation.html` contains a deliberately blocked inline script. The harness observes the resulting `script-src` violation in both engines.
- `test/browser/fixtures/tamper.html` contains a hash-pinned inline script. The runner copies it to a temporary file and appends one byte to the script; both browsers reject it and emit the expected CSP violation.
- `test/browser/fixtures/harness-target.html` supplies an opaque sandboxed frame, visible content, and deterministic throwing network primitives for testing the reusable helpers.
- `test/browser-runner.test.js` executes the runner's failure path in a child process and verifies a non-zero result.

No cryptographic code changed, so no test vectors are applicable.

Negative checks deliberately exercised:

- Deliberate CSP violation: detected in Chromium and Firefox.
- One-byte inline-script tamper: rejected in Chromium and Firefox.
- Deliberate harness assertion failure: child process exits `1`.
- Parent DOM access to opaque sandboxed frame: rejected in Chromium and Firefox.
- `fetch`, `XMLHttpRequest`, and `WebSocket` in the frame: throw in Chromium and Firefox.

## 8. Assumptions made

**Assumed:** Playwright 1.62.1 is the pinned development harness release.

**Basis:** The npm registry reported 1.62.1 on 2026-08-02, and `package-lock.json` records its tarball integrity and the transitive `playwright-core` package.

**If wrong:** A different browser automation implementation would be tested than the one reviewed; the lockfile makes an accidental version change fail `npm ci` review.

**Assumed:** The Playwright-managed Chromium and Firefox binaries are sufficient evidence for browser-observable P0.3a criteria.

**Basis:** ADR-0007 explicitly selects headless Chromium and Firefox for this item.

**Not verified on:** Safari, iOS Safari, Android Chrome, or Tor Browser.

**If wrong:** Platform-specific browser differences remain for P0.19; this item does not claim to close that gap.

**Assumed:** A separate CSP fixture is appropriate until P0.4 adds CSP hash-pinning to the product build.

**Basis:** The current build has no hash-pinned policy, while P0.3a requires the harness to prove it can observe a browser rejecting a tampered hash-pinned script.

**If wrong:** The harness would need to be retargeted to P0.4's built artifact; the reusable assertion itself remains the same.

## 9. What to scrutinise

- The `securitypolicyviolation` listener is installed with `page.addInitScript` before navigation; moving it after navigation would make the negative CSP checks race or miss the event.
- `expectCspViolation('script-src')` accepts browser-reported `script-src-elem` and `script-src-attr` forms while still requiring a matching policy family.
- The runner downloads missing browser binaries on first use. This is explicit development setup and never part of the application build or artifact.
- The harness's network-primitive test uses deterministic throwing stubs in its fixture; P0.6 must apply the same assertions to the real cold realm and CSP guard.

## 10. Self-assessment

- P0.4 is not implemented here. The built product currently has no CSP policy, so the harness's no-violation check on the shell is a smoke check, not proof of product CSP hash-pinning.
- No real mobile or Safari testing was performed.
- No CI workflow was added; CI integration belongs to P0.18.
- The browser binaries are not committed, so a fresh environment needs network access once to install the dev test engines.
