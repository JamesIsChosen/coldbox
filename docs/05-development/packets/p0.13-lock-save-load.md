# PR packet: P0.13 - Lock, unlock, save, load

## 1. Summary

P0.13 adds the first usable vault session workflow on top of the P0.12 format and KDF layers. The warm shell now offers device loading, File System Access saving when the browser exposes it, portable blob download, and a first-class manual encrypted-text handoff. The manual path includes clipboard/select fallback, `navigator.share` when available, numbered multipart QR frames, local QR rendering, and ordered text reassembly. The passphrase field, vault API calls, active session, lock timer, and panic handling remain in the opaque cold frame.

The branch is `p0.13-lock-save-load`. P0.12 is merged into `main`; the authoritative iOS portability re-baseline is on `main` at `cd9f60f0392f122651129aa143f8e4d26e7ad839`; this PR targets `main` and contains that exact governance commit.

The roadmap remains `[~]` while this exact remediation tip awaits fresh independent review. [ADR-0010](../adr/0010-ios-local-html-execution.md) and the authoritative `main` roadmap now explicitly place direct iOS Files-to-Safari execution at P0.19 rather than in P0.13 acceptance. Quick Look is not an execution pass. P0.14 remains unchecked and has not started.

## 2. Scope

### In scope

- Warm-shell device load using File System Access when available and a `.cbx` file-input fallback elsewhere
- Cold-only passphrase entry, empty-vault creation, encrypted-byte load, public-only online unlock, full offline unlock, and lock
- Three save paths: File System Access, blob download, and manual encrypted base64 text with clipboard/select fallback
- `navigator.share` for manual encrypted text when the browser exposes it
- Numbered QR frames in the `CBX-QR/1/<index>/<total>/<base64-payload>` envelope, with a pinned local encoder, frame count/navigation, copy-one/copy-all controls, and ordered reassembly
- Symmetric manual load with whitespace-tolerant raw base64 or complete QR-frame input, protocol-size validation, and rejection of duplicate, missing, inconsistent, oversized, or malformed frames
- Session saves that always fresh-encrypt the public compartment; offline saves also fresh-encrypt the secret compartment, while online saves preserve the original secret nonce and ciphertext opaquely
- Five-minute cold-realm idle auto-lock with passphrase-field, session-key, plaintext, and encrypted working-byte clearing
- `Esc Esc` panic concealment from the warm shell and from the cold frame, with a recovery screen that requires reload
- Explicit private-mode signaling; online unlock and online session saves never derive `cbx/secret/v1`, while an offline signal permits the full opener
- Typed `panic.hide` protocol messages with empty payloads
- Node and Chromium/Firefox coverage for public-only subkey exclusion, save nonce behavior, opaque online secret bytes, `.cbx` naming, blob/manual round-trips, multipart QR rendering/reassembly, and warm/cold panic cleanup
- Roadmap, architecture, crypto-choice, dependency, testing, changelog, build, and packet documentation

### Deliberately out of scope

- Physical Android, macOS Safari, Linux Firefox, Tor, or other device-matrix claims; P0.19 owns those checks. Direct iOS local execution is governed separately by [ADR-0010](../adr/0010-ios-local-html-execution.md).
- Camera-based QR scanning; P0.13 renders QR frames and accepts scanned/copied numbered frame text, while camera capability remains a separate device concern
- Save verification, generational filenames, rollback counters, dirty-state tracking, and public-data editing (P0.14)
- Keyfile unlock (P0.15), wallet creation, and secret-tool workflows

## 3. Security boundary

- The warm shell carries encrypted vault bytes only. It has no `__coldboxVault`, no passphrase input, and no secret-compartment plaintext.
- The cold realm receives `vault.open` ciphertext, reads the passphrase locally, and sends only an empty/public-safe `vault.opened`, encrypted `vault.bytes`, typed status, or generic error messages.
- The cold session requires an explicit mode. Online opening unwraps the DEK and decrypts only the public compartment; the tracked HKDF path observes only `cbx/public/v1`. The secret compartment is not derived or decrypted online.
- Every session save fresh-encrypts the public compartment with a fresh CSPRNG nonce. Offline saves do the same for the secret compartment. Online saves copy the original secret nonce and ciphertext bytes opaquely, without deriving the secret key.
- Closing a session, explicit lock, idle expiry, network-mode transition, and panic hide close the session and clear its keys, plaintext, passphrase field, and encrypted working bytes. The warm shell may retain ciphertext needed for a later reload.
- Panic hide locks before concealing the warm app. A cold-frame `Esc Esc` sends a payload-free typed request to the warm shell.

## 8. Assumptions made

> **Assumed:** `.cbx` is the normative vault extension and `application/octet-stream` is the portable file type.
> **Basis:** ADR-0002 defines the separate encrypted file as `.cbx`; the older `.cbxvault` spelling was removed from the P0.13 surface.
> **If wrong:** An explicit ADR must change the extension everywhere before another save-path implementation proceeds.

> **Assumed:** Numbered QR frames are a text transport envelope, not a new vault format.
> **Basis:** Each frame carries only a bounded slice of the existing encrypted base64 bytes; the receiver validates the sequence and concatenates the original bytes before the existing vault validator runs.
> **If wrong:** The envelope version, payload ceiling, and reassembly rules need a dedicated interoperability decision before external scanners are supported.

> **Assumed:** `navigator.share` is optional and must never be the only manual path.
> **Basis:** Browser support and user cancellation are handled as progressive enhancement; copy/select and numbered QR text remain available.
> **If wrong:** P0.19 should record the device-specific transport failure without weakening the encrypted-file path.

> **Assumed:** Creating a new vault online should produce a public-only vault rather than derive a secret subkey.
> **Basis:** The online-mode invariant is stronger than making creation fail for a user who has not disconnected; an offline creation includes the secret compartment.
> **If wrong:** The creation surface should require offline mode before offering a secret compartment.

> **Decision recorded:** Direct local HTML execution from iOS Files is deferred/blocked under [ADR-0010](../adr/0010-ios-local-html-execution.md), and Quick Look is not equivalent.
> **Basis:** The human device result and the documented platform behavior do not establish a reproducible Files-to-Safari execution contract.
> **If wrong:** A future accepted ADR must identify and security-qualify the supported execution flow before the iOS claim returns.

## 9. What to scrutinise

- Confirm every open and save path is mode-aware: online code never derives `cbx/secret/v1`, online saves preserve secret bytes opaquely, and offline saves use fresh CSPRNG nonces for both compartments.
- Confirm the warm shell never gains a passphrase field or `__coldboxVault` reference through the save/load controls.
- Confirm lock, idle expiry, mode transition, and panic hide close the session and clear the cold passphrase field, keys, plaintext, and working bytes.
- Confirm `.cbx` is used consistently by file pickers, suggested names, downloads, and documentation.
- Confirm manual raw base64 and QR-frame parsing reject incomplete, duplicate, reordered-with-missing, oversized, malformed, or over-ceiling input and never send plaintext through the protocol.
- Confirm QR output is bounded, numbered, count-labeled, locally rendered, and available through copy/select fallback when clipboard/share APIs are unavailable.
- Confirm PR #21 contains current `main` (including the merged P0.12 closeout), targets `main`, and does not reintroduce a P0.12-only PR base.
- Confirm [ADR-0010](../adr/0010-ios-local-html-execution.md) is not silently replaced by Quick Look, a third-party viewer, localhost, a renamed file, or another execution context.
- Do not mark P0.13 `[x]` or start P0.14 before a fresh independent review passes the exact remediation tip and the normal merge workflow completes.
