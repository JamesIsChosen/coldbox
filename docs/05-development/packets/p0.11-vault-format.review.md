Direct source inspection additionally confirmed:

- `vault.js` gets its KDF table from `cryptoLayer.profiles`, including fallback parameters; it does not maintain a second runtime parameter table.
- The header is built from the profile identifier returned by the actual derivation, not from mutable requested/module state.
- Every vault entry point (`create`, `serialize`, `open`, `openPublic`, `parse`, `inspectHeader`) checks the cold health gate before secret-capable work.
- The health gate requires the cold realm ready state, proven CSP canary, installed runtime network guard, required randomness, acceptable AES-GCM crypto state, green airgap state, no lockdown, and guarded vault-operation state.
- `vault.js` does not read `navigator.onLine` or `navigator.connection`; mode resolution consumes `__coldboxAirgap.getNetworkSnapshot()`.
- An online open unwraps/derives the public path only; the secret HKDF/decrypt path is entered only for a proven offline opener.
- The exact 65-byte header slice is reused as AEAD AAD; all header-byte mutations fail through the generic authentication boundary.
- Wrong passphrase and authenticated corruption collapse to `Vault authentication failed.`.
- The documented 64 MiB pre-authentication size refusal is distinct: `Vault exceeds the 64 MiB size limit.`.
- Secret-subkey derivation is private to the module and is not exported.
- The vault API is assembled into the cold realm only.
- `createVaultSession`, `openVaultSession`, public `openSession`, session save/load behavior, and P0.13 session implementation/tests are absent. The only `openSession` references are negative assertions that it is undefined.
