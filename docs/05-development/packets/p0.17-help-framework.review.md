### F2 — The loosened “no machine paths” test misses valid Windows absolute paths

**Severity:** advisory — must fix before merge
**Location:** `test/build.test.js:90-100`
**Observed:** P0.17 changed the machine-path guard to:

```js
/[A-Za-z]:\\(?!u[0-9a-fA-F]{4})|\/Users\/|\/home\//
```

The accompanying comment asserts that real absolute paths are never followed by lowercase `u` plus four hex digits. That is not a valid Windows-path assumption.

Reviewer-owned probe:

```text
ordinary Windows user path: expected=true actual=true
ordinary Windows build path: expected=true actual=true
macOS user path: expected=true actual=true
Linux home path: expected=true actual=true
valid Windows path beginning with u + 4 hex digits:
  expected=true actual=false text=C:\u1234\repo\file.js
JSON-style unicode escape:
  expected=false actual=false text=value:\u003cdiv\u003e
```

A legitimate path such as `C:\u1234\repo\file.js` therefore evades the guard.

**Expected:** The regression test must distinguish JSON `\uXXXX` escaping from an actual drive-qualified Windows path without creating a blind spot for valid path names.

**Required action:** Replace the negative-lookahead shortcut with a test that can recognize actual absolute machine paths while excluding only the intended JSON-escape false positive, and add an adversarial fixture such as `C:\u1234\repo\file.js`.
