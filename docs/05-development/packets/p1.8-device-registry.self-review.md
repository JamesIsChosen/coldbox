## Security review

- The new collection is public-only and enters the same closed protocol map as
  the other Registry collections.
- Unknown device fields, malformed dates/fingerprints/statuses, secret-shaped
  values, and arbitrary text carriers fail closed. `passphraseUsed` is typed as
  boolean and the warm source has no secret-compartment API.
- `clearFields` is schema-validated inside the warm-only Registry module; it
  cannot clear required fields or bypass relationship validation.
- No new message type, CSP permission, network host, runtime dependency,
  derivation path, key material, or cryptographic primitive was introduced.
- Device IDs require `crypto.getRandomValues`; the negative test and the
  browser lockdown matrix cover unavailable randomness and inherited runtime
  failures.
- Locking resets the Device form, hides the workspace, clears the Registry
  store, and clears the session hidden-reveal state.
