## Security checklist

- The exact 65-byte header is used as AAD for DEK wrapping and both compartment AEAD operations.
- Header KDF parameters, cipher id, salt, and compartment lengths are strictly parsed and authenticated; unsupported profiles fail closed.
- The wrapped-DEK block is length-delimited and parses every record without guessing unsupported methods; only the passphrase record is serialized in this item.
- Public and secret keys use distinct HKDF-SHA-512 info strings. The secret subkey is created only when a secret compartment exists and an explicit offline operation is allowed inside the cold layer; it is never exported. Online saves copy the unchanged secret ciphertext and nonce opaquely.
- `crypto.getRandomValues` remains the source for the DEK, salt, nonces, and random padding. The static scan found no `Math.random`, storage, network, or secret-subkey export path in `vault.js`.
- `open` collapses malformed input, KDF, unwrap, AEAD, padding, and JSON failures to `Vault authentication failed.`; a default/explicit online open never derives the secret subkey, and an explicit offline open fails closed while online.
- Session saves re-encrypt public data on every save with a fresh CSPRNG nonce; offline sessions also re-encrypt the secret compartment, while online sessions copy its existing encrypted bytes without deriving its key.
- The complete diff was read, `git diff --check` passed, and the reserved `.review.md` path remains absent for independent review.

## Verdict rationale

Both roadmap criteria are met and reproduced by independent test processes, alternate-environment builds, deliberate failure checks, and both browser engines. The internal cold session primitive exists only to enforce the v1 save nonce rule for P0.13 and does not expose a warm-shell vault operation. No PR was merged.
