## Security checklist

- The exact 65-byte header is used as AAD for DEK wrapping and both compartment AEAD operations.
- Header KDF parameters, cipher id, salt, and compartment lengths are strictly parsed and authenticated; unsupported profiles fail closed.
- The wrapped-DEK block is length-delimited and parses every record without guessing unsupported methods; only the passphrase record is serialized in this item.
- Public and secret keys use distinct HKDF-SHA-512 info strings. In the current remediation candidate the secret subkey is created only when a secret compartment exists, the cold health gate is proven, and the shared airgap snapshot reports offline; it is never exported.
- `crypto.getRandomValues` remains the source for the DEK, salt, nonces, and random padding. The static scan found no `Math.random`, storage, network, or secret-subkey export path in `vault.js`.
- `open` collapses malformed input, KDF, unwrap, AEAD, padding, and JSON failures to `Vault authentication failed.`; the documented public 64 MiB size refusal is intentionally distinct. A default/explicit online open never derives the secret subkey, and an explicit offline open fails closed unless the shared airgap snapshot reports offline.
- No session/save API remains in P0.11. Lock/unlock/save/load lifecycle behavior is deferred to P0.13 by explicit user decision A.
- The independent `.review.md` report now exists and remains reviewer-owned; remediation does not modify it.
