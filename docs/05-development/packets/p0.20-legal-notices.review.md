## 4. Findings

### F1 — Blocking — P0.20 makes the real Chromium/Firefox harness fail before Firefox runs

**Location:** `scripts/run-browser-harness.js`, `verifyHelpFramework()` and the P0.20 addition to the contextual-help surface.

**Observed:** P0.20 adds a sixth `button.help-context-button[data-help-topic]` for `glossary:appropriate-legal-notices`. After Chromium successfully verifies the new Appropriate Legal Notices offline, `verifyHelpFramework()` still asserts that exactly five contextual-help buttons must survive initialization:

`assert.equal(settledButtonCount, 5, ...)`

The real review run therefore exits 1 with:

`Chromium: all five contextual help buttons must survive app initialization, found 6`

and

`6 !== 5`

Because the harness runs engines serially, Firefox is never reached.

**Expected:** The branch's full `npm run test:browser` must pass end-to-end in both Chromium and Firefox, and the help-framework regression must account for every shipped contextual-help button, including the new P0.20 mapping.

**Required action:** Update the help-framework browser regression to recognize and exercise the complete post-P0.20 contextual-help set, including `glossary:appropriate-legal-notices`, then run the full harness successfully in both Chromium and Firefox. Do not merely bypass or remove the settled-DOM regression.

### F2 — Advisory — `NO_MACHINE_PATHS` no longer checks machine paths embedded through `LICENSE`

**Location:** `test/build.test.js`, new `stripEmbeddedLicenseText()` and the changed no-machine-path assertion.

**Observed:** P0.20 changes the standing output-leak regression from checking the entire built HTML to checking:

`stripEmbeddedLicenseText(html.toString('utf8'))`

The whole `PROVENANCE_LICENSE_TEXT` assignment is removed before `NO_MACHINE_PATHS` runs. The author rationale says this is safe because `test/legal-notices.test.js` separately proves byte identity to the repository `LICENSE`, but byte identity proves only that the build matches its input; it does not prove that the input is machine-path-free.

The independent probe appended this literal line to `LICENSE` in a disposable exact-head clone:

`REVIEW MACHINE PATH SENTINEL: C:\Users\reviewer\coldbox\secret`

Then it ran:

`node --test --test-concurrency=1 test/build.test.js test/legal-notices.test.js`

Result: **21/21 PASS, exit 0**. The machine path is embedded into `build/coldbox.html`, the no-machine-path test strips it before scanning, and the byte-identity test accepts it because the modified `LICENSE` is its source of truth.

This weakens a standing build-output regression in code changed by P0.20.

**Expected:** A literal machine-specific absolute path introduced through any build input, including `LICENSE`, must still make the machine-path regression fail.

**Required action:** Preserve the JSON-escape false-positive fix without creating an unchecked region. For example, independently scan the raw/parsed licence text with the machine-path rule before excluding its JSON-encoded assignment from the whole-document scan. Add a negative regression that injects a real Windows machine path into `LICENSE` and requires non-zero test failure. Equivalent implementations are acceptable if they restore complete coverage.

### F3 — Advisory — the committed bundle-size delta is inaccurate under the repository-pinned runtime

**Location:** `CHANGELOG.md`, `docs/05-development/ROADMAP.md` P0.20 current-state note, and `docs/05-development/packets/p0.20-legal-notices.md`.

**Observed:** Those records state:

`1,040,074 -> 1,080,408 bytes, +40,334 bytes (≈ +39.4 KB)`

The independent review built both exact commits using the repository-pinned Node `v24.16.0`:

- base `e41f9d94...`: **1,040,057 bytes**
- P0.20 `40c288dd...`: **1,080,408 bytes**
- actual delta: **+40,351 bytes**

The 17-byte discrepancy does not threaten the size ceiling; the result remains far below both the 3 MB target and 4.5 MB hard cap. But P0.20's acceptance criterion explicitly requires the delta to be recorded, so the committed record must be accurate.

**Expected:** The recorded baseline, final size, and delta must match reproducible builds of the exact base/head under the repository-pinned runtime.

**Required action:** After remediating F1/F2, rebuild the then-current exact base and remediation tip with Node `24.16.0` and update every P0.20 size record to the resulting numbers. Because remediation may change the tip size, do not simply substitute `+40,351` without remeasuring the final candidate.
