## 5. Security impact

- **Realm boundary, message schema, CSP, vault format, derivation, randomness:** not touched by this branch. The Learn page lives entirely in the warm shell; no new message type was added; no cold-realm file changed.
- **New CSP-relevant surface:** none — no new inline script/style block beyond what the existing build already hashes (`scripts/build.js`'s `hashInlineBlocks` covers the whole assembled `<script>`/`<style>` regardless of what's inside them; no new `<script>`/`<style>` tag was added).
- **New `localStorage` key:** `coldbox-help-depth`. This is a UI preference (which reading-depth to show), not secret material, and CONTRIBUTING.md explicitly permits `localStorage` for UI preferences (the existing `coldbox-theme` key is the precedent). `scripts/lint.js` only forbids `localStorage` inside `src/cold/` (the secret-handling realm); `src/main.js` is outside that path.
- **New `innerHTML` usage:** `renderHelpGlossary`/`renderHelpGuides` assign `body.innerHTML = term.byDepth[depth]`, and `linkifyGlossaryTerms` assigns `span.innerHTML = replaced`. Both sources are build-time-compiled from repository markdown (not user input, not vault content, not anything from the cold realm), and `scripts/help-content.js`'s `escapeHtml`/`renderInline` escape all raw text before wrapping it in a small fixed whitelist of tags (`p`,`h3`–`h6`,`ul`,`ol`,`li`,`table`,`thead`,`tbody`,`tr`,`th`,`td`,`code`,`pre`,`strong`,`em`,`blockquote`,`hr`,`button` for glossary-term spans) — no script-capable tag is ever emitted, and CSP would refuse to execute one even if it were. **What to scrutinise if this claim is wrong:** `renderInline`'s link-handling regex and the `linkifyGlossaryTerms` text-replacement path, since those are the two places raw text is spliced back into an HTML string outside the main block-level escaping loop — see §9.
- **No new `connect-src` host.** No new message type.

## 8. Assumptions made

- **Depth-block granularity is per-passage, not per-file** (ADR-0016). The existing `docs/03-guides/README.md` documented the `:::` syntax but not its scope; I chose per-passage because guides are predominantly procedural and forcing whole-file triplication would mean rewriting identical steps three times. Reviewable, and reversible — a file with one group spanning its entire body already behaves as "whole-file" under this model.
- **Default depth is `plain`**, matching SPEC.md's ordering (plain → working → technical) and the safest fallback direction. Not stated explicitly anywhere as the *default*; this is a judgment call, recorded here per AGENTS.md §4.
- **The four "Things people get wrong" glossary entries are deliberately kept single-depth.** They're corrections/warnings, not concepts needing three levels of explanation — the plain-English callout *is* the technical one. This means they always trigger the build warning; I judged that honest and correct rather than writing three redundant near-identical copies to silence the warning. A reviewer could reasonably disagree and require they be wrapped too (trivially: wrap the existing text in `::: plain` and duplicate it into `::: working`/`::: technical`).
- **The capability-panel contextual-help button intentionally targets nonexistent content** (`guide:capability-self-check`) to prove the fallback path works, rather than being mapped to existing content. This is a deliberate test fixture left in the shipped markup, not an oversight — flagged explicitly here and in the roadmap/changelog so it isn't mistaken for a bug.
- **`test/build.test.js`'s "no machine paths in the output" regex was loosened** (`/[A-Za-z]:\\(?!u[0-9a-fA-F]{4})|\/Users\/|\/home\//`) after the real docs content started producing coincidental `letter:\` matches from `<`-escaped tag boundaries in ordinary prose (a sentence ending a word right before an escaped `<strong>`). The fix excludes the unicode-escape shape specifically rather than weakening the check generally — reasoning is inline in the test file. **This is exactly the kind of change I'd want a second pair of eyes on**, since it touches a security-adjacent leak-detection test.

## 9. What to scrutinise

- **The alias-parsing bug this session found and fixed in `compileGlossary`.** The original regex treated *any* parenthetical after a term as an alias list — including `"Vault (in Coldbox)"` and `"Cold realm / warm shell (in Coldbox)"`, which would have produced a bogus `"in Coldbox"` alias, and `"xpub (extended public key; also ypub, zpub, vpub)"`, whose semicolon-separated definition fragment would have been mangled into the alias list too. Fixed to only extract aliases when the parenthetical explicitly contains the word "also". Covered by `test/help-content.test.js`'s alias-parsing tests, but **I would specifically re-derive the fix myself rather than trust my own regex reasoning** — this is exactly the kind of off-by-a-word-boundary bug that's easy to get subtly wrong twice.
- **The `jsonScriptLiteral()` bundle-size interaction.** This session discovered, empirically, that a large amount of compiled prose pushed through the existing `<`/`>`/`&` → `\uXXXX` escaping helper costs roughly 5 extra bytes per angle bracket. That helper is shared with `PROVENANCE_LIBRARIES` and the cold-realm document and predates this item; I did not change it, because narrowing its escaping (e.g. to only sequences that could form `</script`) is a security-relevant change to shared code that deserves its own review, not a drive-by fix bundled into a content-compiler PR. Flagged in the ADR, CHANGELOG, and SPEC.md as an open, unresolved finding.
- **The zero manual-browser-testing gap, stated plainly again:** every claim in §4 about DOM behavior (depth switching, search, contextual help, inline glossary) rests on code review against the actual selectors/ids in `src/index.html`/`src/main.js`, not on having watched it run. I found and fixed one real bug this way already (§4's Learn-page assertion originally checked for text that doesn't appear in the actual glossary content — caught by re-reading my own fixture against my own prose, not by running it). There may be others like it that only running the harness would catch.
- **`normalizeLocation`'s changed collapsing behavior.** It now preserves a `#route/topic` hash instead of always collapsing to `#route`, to support shareable deep links into Learn content. This is a small, deliberate behavior change to existing routing code (not new-route-only code) — worth checking it doesn't interact oddly with any other route that might someday use a `/`-suffixed hash for its own purposes.

- **What I did not do that arguably should have been done:** the P0.1–P0.16 backfill (explicitly out of scope for this stop, not silently dropped); wrapping the four "Things people get wrong" entries in depth blocks (judgment call, see §8); narrowing `jsonScriptLiteral()`'s escaping to recover bundle size (deferred as a separate, shared-code change); actually running `npm run test:browser` (blocked by sandbox network policy, not a choice).
