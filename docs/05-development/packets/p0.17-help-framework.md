## 4a. Independent review findings — remediation and re-verification

PR #29 was independently reviewed on 2026-08-07 and returned **FAIL** with 4 findings (1 blocking, 3 advisory). All four are fixed in this branch:

**F1 (blocking) — browser harness broken before P0.17's own checks run.** `verifyDevOnlyDependency()` in `scripts/run-browser-harness.js` copied only `scripts`, `src`, and `vendor` into its dependency-free temporary build root. P0.17's build now also reads `docs/00-overview/glossary.md` and `docs/03-guides/*.md`, so that temporary build failed with `ENOENT` before `run()` ever entered the Chromium/Firefox loop — `verifyHelpFramework()` was never reached, regardless of whether browser binaries were present. **Fix:** added `docs` to the list of copied directories, mirroring the same fix already applied for `.git` for the identical reason (P0.16 F4). **Re-verification status:** the reviewer confirmed with real network access that Chromium and Firefox both install and launch cleanly in this repository, meaning the original failure was 100% this fixture bug. I could not re-run the fixed harness to completion myself (this sandbox still can't download Playwright binaries — see §3) — a maintainer or the re-reviewer with real network access needs to confirm `npm run test:browser` now reaches and passes `verifyHelpFramework()` in both engines.

**F2 (advisory) — machine-path regression test had a blind spot.** `test/build.test.js`'s "no machine paths in build output" guard excluded any `letter:\` sequence followed by `u` + 4 hex digits, on the theory that real absolute paths are never followed by that shape. The reviewer showed that's false: a real path like `C:\u1234\repo\file.js` would evade the check. **Fix:** the exclusion now names the exact three sequences `jsonScriptLiteral()` produces (`\u003c`, `\u003e`, `\u0026`) instead of the general 4-hex-digit shape, so any other `letter:\u`-shaped text — including a coincidental real path — still gets flagged. Added a dedicated test (`the no-machine-paths guard flags real absolute paths, including ones shaped like a JSON escape, but not the actual JSON escapes jsonScriptLiteral emits`) covering the reviewer's exact adversarial case plus the legitimate escape shapes. **Re-verified:** `node --test test/build.test.js` → 12/12 pass (was 11; +1 for the new test).

**F3 (advisory) — packet evidence didn't reproduce.** The prior packet stated Node `v22.22.3` without disclosing the pin mismatch, a build hash (`94629bcc...`) that doesn't match a fresh build of the same commit, and a manually-summed `npm test` count of 155 that didn't even reproduce from its own displayed per-file numbers. **Fix:** this section (§3) was re-run from scratch against the current tip and states the toolchain gap plainly; the real build hash and the real, non-manually-summed test count are both quoted directly from tool output and both independently match the reviewer's own numbers exactly (ad2e50ce... and 132, respectively).

**F4 (advisory) — tracked documentation contradicted the final state.** ADR-0016 said the backfill remained incomplete (7/9 guides, all in-app-copy backfill still plain-only) when the actual final tree has zero help-content warnings; ROADMAP.md, the packet, and CHANGELOG.md all said 46 glossary entries when the compiled source has 51. **Fix:** ADR-0016's "Negative" section now marks that line as historical (true of an earlier draft, not the submitted branch) and states the final numbers; ROADMAP.md's P0.17 current-state note, CHANGELOG.md, and this packet are all corrected to 51 entries throughout, verified directly against `compileHelpContent()`'s output (`c.content.glossary` sums to 51 terms across 8 categories) and the reviewer's independent DOM count.

## 5. Security impact

- **Realm boundary, message schema, CSP, vault format, derivation, randomness:** not touched by this branch. The Learn page lives entirely in the warm shell; no new message type was added; no cold-realm file changed.
- **New CSP-relevant surface:** none — no new inline script/style block beyond what the existing build already hashes (`scripts/build.js`'s `hashInlineBlocks` covers the whole assembled `<script>`/`<style>` regardless of what's inside them).
- **New `localStorage` key:** `coldbox-help-depth`. A UI preference (which reading-depth to show), not secret material — CONTRIBUTING.md explicitly permits `localStorage` for UI preferences (the existing `coldbox-theme` key is the precedent), and `scripts/lint.js` only forbids `localStorage` inside `src/cold/`, which `src/main.js` is outside.
- **New `innerHTML` usage:** `renderHelpGlossary`/`renderHelpGuides` assign `body.innerHTML = term.byDepth[depth]`, and `linkifyGlossaryTerms` assigns `span.innerHTML = replaced`. Both sources are build-time-compiled from repository markdown (not user input, not vault content, not anything from the cold realm), and `scripts/help-content.js`'s `escapeHtml`/`renderInline` escape all raw text before wrapping it in a small fixed whitelist of tags (`p`,`h3`–`h6`,`ul`,`ol`,`li`,`table`,`thead`,`tbody`,`tr`,`th`,`td`,`code`,`pre`,`strong`,`em`,`blockquote`,`hr`,`button` for glossary-term spans) — no script-capable tag is ever emitted, and CSP would refuse to execute one even if it were. **What to scrutinise if this claim is wrong:** `renderInline`'s link-handling regex and `linkifyGlossaryTerms`'s text-replacement path, since those are the two places raw text is spliced back into an HTML string outside the main block-level escaping loop — see §9.
- **No new `connect-src` host.** No new message type.

## 8. Assumptions made

- **Depth-block granularity is per-passage, not per-file** (ADR-0016). Reversible — a file with one group spanning its entire body already behaves as "whole-file" under this model.
- **Default depth is `plain`**, matching SPEC.md's ordering (plain → working → technical) and the safest fallback direction. A judgment call, recorded per AGENTS.md §4.
- **The "Things people get wrong" glossary entries are wrapped in depth blocks too** — completed after an earlier draft left them single-depth; ADR-0016 previously misdescribed this as still incomplete (F4, corrected).
- **New glossary category "App features (in Coldbox)"** backs five previously-undocumented P0.1–P0.16 features as glossary entries rather than invented step-by-step guides, since none of these are user-performed workflows. Reversible if a reviewer would rather see dedicated guide files.
- **F2's fix ties the machine-path exclusion to the exact three sequences `jsonScriptLiteral()` currently emits**, rather than a general heuristic. This is precise but means the test needs updating if that function's escape set ever changes — a `test/help-content.test.js`/`test/build.test.js` maintenance note worth keeping in mind, not raised as its own finding here since it's the direct, narrow fix the reviewer asked for.

## 9. What to scrutinise

- **The F1 fix itself, since it's unexecuted by me.** `scripts/run-browser-harness.js`'s `verifyDevOnlyDependency()` now copies `docs` alongside `scripts`/`src`/`vendor`/`.git`. This is a small, mechanical change, but it's the one piece of this remediation nobody has watched run in this session — see the top of this packet.
- **The alias-parsing bug found and fixed in `compileGlossary`** (unchanged from the prior packet, already independently verified by the reviewer as passing scrutiny): the original regex treated *any* parenthetical after a term as an alias list. Fixed to only extract aliases when the parenthetical explicitly contains the word "also". Covered by `test/help-content.test.js`.
- **The `jsonScriptLiteral()` bundle-size interaction.** Shared with `PROVENANCE_LIBRARIES` and the cold-realm document; not changed here since narrowing its escaping is a security-relevant change to shared code deserving its own review. The reviewer explicitly declined to raise this as a new finding, since it's already disclosed in SPEC.md/ADR-0016 and the shipped artifact is within the documented overall budget.
- **`normalizeLocation`'s changed collapsing behavior** — now preserves a `#route/topic` hash instead of always collapsing to `#route`, to support shareable deep links into Learn content. Worth checking it doesn't interact oddly with any other route.
