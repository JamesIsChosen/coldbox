## 2. Scope and acceptance

The canary remains explicitly opt-in and off by default. It establishes a
baseline only after the user enables it, re-reads the clipboard once after a
delay without user action, and reports an observed change as affirmative
clipboard volatility. Denied permission, absent APIs, and unexpected read
failures are visibly unavailable; ordinary address comparison remains usable.

The remediation specifically closes these race conditions:

- `permissions.query()` and clipboard API/property access are promise-contained,
  so synchronous browser exceptions become the normal unavailable path;
- an enable that becomes stale after disable or retry cannot change the newer
  state, baseline, timer, or UI;
- stale permission/read failures cannot overwrite a newer armed state;
- the warm UI handles an unexpected rejected enable/retry visibly and leaves
  the toggle off.

The change message continues to name clipboard managers, sync tools, and
remote-desktop clients before malware. The canary is warm-only and never enters
the opaque cold frame.

## 3. Dependency merge and security boundary

The original PR #46 branch was based on the old P1.12 head. It was merged with
the pushed P1.12 remediation at `17a268f`, resolving only the shared warm-shell
registrations in `src/index.html` and `src/main.js`; both P1.12 address
verification and P1.13 canary controls are present. No force-push or P1.12
mutation was used.

The canary carries no vault, seed, private-key, xprv, passphrase, or
secret-compartment data. It reads only the browser's public clipboard API in the
warm realm, reports state enums and bounded user-facing copy, and never sends
clipboard text across the realm boundary. It does not claim that a stable read
proves clipboard safety.

## 6. Browser evidence

The new P1.13 matrix uses deterministic pre-navigation browser controls (not a
real OS permission prompt) and drives the shipped UI through:

- fresh off-by-default state with zero implicit reads;
- permission denied with visible unavailable state;
- retry to granted without reload;
- API absence while the address comparison remains enabled;
- a delayed clipboard change with benign causes named before malware.


Not tested by this author session:

- a real browser/OS permission prompt;
- physical clipboard managers, remote-desktop clients, or mobile clipboard
  behavior;
- iOS Safari or Android Files execution.

Those limits are explicit; the deterministic UI matrix and unit tests do not
claim to replace physical-device validation.
