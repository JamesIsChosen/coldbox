## Findings

**F1 — CSPRNG-only entropy is not implemented.** `guaranteedBits()` ignored `csprngBytes`, so a CSPRNG-only session had 0 guaranteed bits and could not generate, even though SPEC lists CSPRNG as an Entropy Lab source in its own right and the guide describes CSPRNG as "instant."

**F2 — "Outputs 128–256 bits to Seed Forge" is literally unmet.** The packet itself admitted Seed Forge/P1.3 does not exist and the output is carried nowhere. The review protocol does not allow reviewers to reinterpret an unmet criterion as satisfied.

**F3 — Card undo is broken in the UI.** Drawing a card removed its `<option>` element directly; undo restored the internal accumulator state but never restored the option to the selector, desyncing the DOM from the session.

**F4 — Mixed output becomes stale.** Adding further entropy or CSPRNG input, or changing the target size, after a mix did not clear the previously displayed mixed result.

**F5 — The implemented cryptographic formula disagreed with the canonical documentation.** The code computed `SHA-256(0x00000000 ‖ (manual XOR CSPRNG))`; the guide states the literal formula `SHA-256(manual XOR CSPRNG)`. The reviewer's independent SHA-256 implementation reproduced both formulas and confirmed they diverge.

**F6 — CSPRNG material is reused.** Calling `mix()` twice without an intervening CSPRNG draw produced the same output from the same retained CSPRNG bytes, despite the UI and packet describing them as fresh.

**F7 — The documented "2 shuffles" path for 256-bit card entropy could not be entered.** There was only one 52-card pool with no second-shuffle/reset operation.

**F8 — SPEC requires mixing "with a diagram."** No diagram was added; the packet's acceptance-criteria table dropped that phrase rather than checking it verbatim.

**F9 — Browser verification remains missing.** `AGENTS.md`'s Definition of Done requires testing on at least one desktop and one mobile browser from `file://`; the packet explicitly marked the entire device matrix untested.

**F10 — Packet build evidence was stale.** The packet claimed hash `543c887c…` at 1,128,409 bytes, while exact-head CI produced byte-identical Windows/Ubuntu artifacts at `f4d67f18…` and 1,128,411 bytes. The CI workflow is designed to build the real PR head SHA, and the packet's evidence did not match it.

**F11 — The reviewer could not complete the mandatory independent clean checkout/vendor/build run.** Their shell could not resolve GitHub; hosted CI passed, but the review protocol requires the reviewer to reproduce those checks independently, which their environment did not permit.

## What the reviewer confirmed was sound

- Malformed dice/card/hex values and unsupported target sizes fail closed.
- A short CSPRNG buffer throws rather than degrading silently.
- `bitLength(range) - 1` is sound — exactly `floor(log2(range))` for a positive integer range.
