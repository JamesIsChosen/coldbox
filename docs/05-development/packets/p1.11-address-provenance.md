## Scope and acceptance

The implementation adds public schema version 2 and the four documented Address fields: `addressOrigin`, `verificationState`, `lastColdVerifiedAt`, and `verifiedAgainstXpub`. Legacy schema-1 or schema-less public compartments migrate to schema 2 with `manual` and `unverified` defaults. No verification state is inferred.

New addresses default to `manual` and `unverified`. An account xpub change automatically moves related `cold-verified` addresses to `cold-verified-stale` while preserving the old xpub and timestamp as evidence. The Registry lists each address's state and displays an explicit count of never-verified addresses.

This meets the roadmap acceptance criteria: previous-schema vault data opens; `verificationState` is never inferred; xpub changes stale verified addresses automatically; and stale entries are not displayed as verified.

## Security boundary

All new fields are public metadata. The protocol sanitizer validates closed enums, timestamps, xpubs, and schema versions; rejects future schema versions; strips unknown fields; and continues rejecting secret-shaped content. No new secret-bearing message type or realm crossing was added. A `cold-verified` state can only be represented with verification timestamp and xpub evidence; P1.12 will add the actual cold re-derivation event.

## Assumptions and scrutiny points

- A missing public schema is treated as legacy schema 1, as required for opening pre-P1.11 vaults.
- Legacy addresses default to `manual` rather than inferring `derived`; a future cold verification flow must explicitly write the verified evidence fields.
- Clearing or changing an account xpub makes existing verified addresses stale; the stale evidence is retained for auditability.

Scrutinize the migration default and the xpub-change transition. The most important negative test is that stale records retain `cold-verified-stale` and are never rendered with the `Cold verified` label.

## Known limits

P1.11 does not claim that a warm-side state change itself proves an address. The actual cold re-derivation and clipboard verdict are P1.12. Physical printer/scanner testing remains outside this item; the browser harness passed the Registry and file:// boundary flows.
