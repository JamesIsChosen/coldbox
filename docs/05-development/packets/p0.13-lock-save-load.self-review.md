## Security checklist

- The warm source and template contain no `__coldboxVault`, passphrase field, `openPublic`, `deriveSecretSubkey`, or `cbx/secret/v1` path.
- `vault.open` carries ciphertext only; the cold passphrase input is `spellcheck="false"` and is cleared on explicit lock, idle lock, mode transition, and panic hide.
- The online opener never derives `cbx/secret/v1`; full opener selection is cold-only and requires an offline mode signal.
- Every session save creates a fresh public nonce; offline saves create a fresh secret nonce; online saves copy the original secret nonce/ciphertext without deriving its key.
- Closing the session zeroes keys, plaintext, current encrypted bytes, pending bytes, and the passphrase field. Browser assertions inspect the locked/cleared cold state after both panic paths.
- The warm shell receives only sanitized public data, encrypted bytes, typed status, or generic error messages. The `panic.hide` message has an empty payload.
- Manual raw base64 and QR-frame parsing enforce the vault size ceiling, QR count/payload limits, sequence completeness, and duplicate rejection before the existing encrypted-byte validator runs.
- `.cbx` is the only P0.13 file extension in the picker, suggested name, download name, packet, and changelog.
- The local QR encoder is pinned and verified offline; no network dependency was added to the runtime bundle.
- The blob URL is revoked after download scheduling; File System Access errors and user cancellation are rendered generically.
- The opaque sandbox, CSP, network throw contract, global-message discard, runtime airgap guard, and browser lockdown negatives remained green in both browser engines.
