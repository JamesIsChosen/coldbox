## 1. Summary

This item adds a cold-only, Coldcard-compatible Seed XOR implementation for
2–4 complete BIP-39 parts from 12-, 18-, or 24-word source phrases. It adds
deterministic and CSPRNG-derived masks, independent vector tests, and a masked
timed-reveal UI that never sends or persists the phrases. The user-facing guide
and ADR document the N-of-N property, entropy domain, Coldcard construction,
and separate BIP-39 passphrase boundary.

## 2. Scope

Included:

- `src/cold/seed-xor.js`: entropy-domain split/combine APIs, deterministic
  Coldcard masks, random masks, input validation, and transient zeroization.
- Cold-realm markup and wiring in `src/cold/index.html`, `src/cold/main.js`,
  and `src/cold/styles.css`, including masked inputs/outputs, 30-second reveal
  timers, count and wordlist selection, and lock/teardown clearing.
- Independent Node tests, browser-harness coverage, and build assembly.
- The P2.3 roadmap marker, changelog, dependencies note, user guide, ADR, and
  guide index entry.

Deliberately not included: SLIP-39, Shamir39/raw SSS, vault recovery records,
threshold recovery, BIP-39 passphrase splitting, clipboard/download/storage,
new message types, or any warm-realm Seed XOR surface. Those belong to other
roadmap items or are explicitly outside Seed XOR.

## 5. Security impact

- **Realm boundary:** Yes. Secret phrases, entropy buffers, generated parts, and
  the combined phrase are processed only in the cold realm. No new message type
  or warm-facing state was added. The browser harness asserts that
  `window.__coldboxSeedXor` is absent from the warm page and that teardown
  clears the cold state.
- **Message schema:** No change. Seed XOR has no message path and cannot carry a
  mnemonic, private key, xprv, passphrase, or other secret-compartment value.
- **CSP/network:** No new host or capability. The existing cold CSP remains
  `connect-src 'none'`; Chromium and Firefox runtime probes reported blocked
  fetch, XHR, WebSocket, EventSource, and `sendBeacon` calls.
- **Randomness:** Random masks require `crypto.getRandomValues` and fail closed
  when unavailable. The repository lint and focused source test reject
  `Math.random`, `eval`, and `new Function` in this module.
- **If this were wrong:** A bad entropy domain or mask construction could make
  Coldbox unable to recover or interoperate with a written backup. A boundary
  or teardown mistake could expose the original phrase or a generated part to
  the warm document or a later session. Those risks are addressed by the
  independent Coldcard vector, Node reference, source-surface checks, and
  browser teardown tests, but the external reviewer must re-check the exact
  algorithm and all cold/warm paths.

## 6. Test evidence

New focused tests in `test/seed-xor.test.js` prove:

- interoperability with Coldcard's published three-part 24-word example;
- deterministic masks against an independent Node SHA-256 implementation for
  all supported entropy lengths;
- entropy XOR and any-order reconstruction;
- random round trips for 12, 18, and 24 words with 2, 3, and 4 parts;
- invalid checksum, mismatched length, unsupported count/mode, and unavailable
  randomness rejection; and
- absence of warm-boundary and persistence surfaces.

The vector source is [Coldcard's published Seed XOR documentation](https://github.com/Coldcard/firmware/blob/master/docs/seed-xor.md);
the construction is cross-checked against the [published firmware implementation](https://github.com/Coldcard/firmware/blob/master/shared/xor_seed.py).
The deterministic reference in the test is independently implemented with
Node's built-in `crypto.createHash`, not imported from the product module.

The browser harness adds both-engine checks for the official vector, random
flow, masked output, explicit reveal, incomplete sets, warm isolation, and
teardown. The intentional forbidden-construct build failure exited with code
1, rather than merely printing an error.

Not tested: physical iOS local execution, Android Files, macOS Safari, macOS
Chrome, Linux Firefox, Tor Browser, or a hardware wallet. No production seed,
private key, or vault was used or committed.

## 8. Assumptions made

- The Coldcard documentation and firmware source reviewed on 2026-08-12 are
  the authoritative external interoperability references for this roadmap
  item. If Coldcard changes the prefix, index encoding, hash count, supported
  lengths, or part-count semantics, the vector and ADR require a new review.
- Seed XOR's random construction uses double-SHA-256 of CSPRNG bytes before
  truncation, matching the published firmware shape; it is not claimed to be
  threshold recovery or a substitute for a separately backed-up BIP-39
  passphrase.
- All vendored BIP-39 wordlists may use the same entropy operation, while
  English is the documented Coldcard interoperability choice.
- Timed reveal is a usability control, not a guarantee against screenshots,
  shoulder surfing, browser memory forensics, or malicious host hardware.

## 9. What to scrutinise

Review the exact deterministic mask bytes in `src/cold/seed-xor.js` against the
Coldcard source, especially the zero-based index, ASCII suffix, double hash,
and final XOR part. Then inspect the cold-only wiring and teardown paths in
`src/cold/main.js`: source and part fields are cleared immediately after
processing, output strings remain only in cold-local state, and reveal timers
must not outlive a lock. Finally, verify that no future refactor turns the
returned entropy or mnemonic into a warm message, storage record, clipboard
payload, or passphrase surrogate.

## 10. Self-assessment

- The implementation is most sensitive to a future interpretation change in
  Coldcard's random-mask construction; the published deterministic vector does
  not by itself prove random-mode interoperability.
- Browser automation covers Windows Chromium and Firefox only. Physical mobile,
  Safari, Tor, and hardware-wallet execution were not performed.
- JavaScript strings cannot be explicitly zeroized; the implementation clears
  all DOM and object references on use/lock, but this is not a claim of perfect
  garbage-collector erasure.
- Future threshold-share work must not reuse this API or describe Seed XOR as
  SLIP-39/Shamir recovery. P2.4 is the separate threshold/raw-SSS item.
