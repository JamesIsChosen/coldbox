# P1.12 - Clipboard round-trip address verification PR packet

## 1. Summary

P1.12 adds whole-string clipboard round-trip, inbound, and batch address verification, keeping the warm registry-match claim separate from cold re-derivation authority. This author branch was reconciled after PR #45 was closed when its stacked P1.11 base was deleted: the reconciled branch now contains the reviewed P1.11 merge commit on main while preserving the original P1.12 product commits. No P1.13 files or commits were changed.

In scope:

- character-exact comparison with first-divergence reporting;

- cold re-derivation and provenance update ordering;
- enum-only address verification protocol messages;
- author-side reconciliation onto main at the merged P1.11 commit;
- refreshed author evidence and self-review.

Deliberately not in scope:

- physical hardware-wallet authenticity;

## 5. Security impact

The reconciliation itself does not alter the realm boundary, CSP, vault format, randomness, or cryptographic choices. It brings the reviewed P1.11 tree onto the P1.12 branch without overwriting the P1.11 fixes.

P1.12 adds the already-specified address.verifyRequest and address.verifyResult message types. They carry only public address strings, record/account references, indexes, closed outcome codes, divergence indexes, timestamps, and public xpub evidence. They do not carry mnemonics, private keys, xprvs, passphrases, secret-compartment plaintext, or free-form result prose. The full protocol suite passes the secret-field rejection tests.

No new connect-src host is introduced. The cold realm retains connect-src 'none', opaque sandboxing, and the existing runtime guards inherited from main.
