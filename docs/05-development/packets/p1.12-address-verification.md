## Scope and acceptance

The warm shell now provides round-trip, inbound, and batch address checks. The comparison is whole-string and reports the first divergence index. Bech32 is case-insensitive, Base58 is case-sensitive, and mixed-case EVM values with a failing EIP-55 checksum return `checksum-invalid` rather than `mismatch`.

The protocol adds `address.verifyRequest` and `address.verifyResult` with closed, public-only schemas. The cold realm compares the selected record, attempts an actual re-derivation from the current cold Seed Forge identity, updates public verification evidence only after the derived value matches the record, and returns enum outcomes. A locked vault returns `vault-locked`; it never reports `no-record` because the registry is unavailable.

The Registry state is shown inline on every result. A warm match does not imply cold authority, and `unverified`, `cold-verified-stale`, and `unverifiable` remain visibly distinct.

## Security boundary

The candidate, record identifiers, index, outcomes, divergence index, timestamp, and public xpub evidence are the only values crossing the message boundary. No mnemonic, seed, private key, passphrase, xprv, or secret-compartment plaintext is accepted by the new message validators or returned by the cold handler. The cold realm borrows Seed Forge bytes for derivation and does not return or retain them.

## Assumptions and scrutiny points

- EIP-55 is implemented in the warm/cold public comparison layer with a self-contained Keccak-256 implementation; no network or runtime dependency is introduced.
- Cold re-derivation uses the current Seed Forge identity and the public account path/xpub when available. If the identity is not available, the existing state is not promoted to verified.
- A public-data acknowledgement can arrive before the correlated verification result; the warm shell accepts it only while that verification request is pending.

Scrutinize the Keccak checksum implementation, divergence index, and the ordering of `publicData.updated` versus `address.verifyResult`. These are the least-confidence parts of the change.
