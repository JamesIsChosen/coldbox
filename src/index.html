▼ How the boundary is built ▼

01

A toolkit, not a wallet

Coldbox holds no coins, reaches no blockchain to move them, and signs nothing. It is a companion to your hardware wallets: it checks their work, manages your backups, and keeps the records.

02

Portable by default

One file on a USB stick, opened by double-clicking. The interface is designed for a narrow phone screen up through a desktop window, with no server and no install step.

03

Secrets get their own boundary

The sealed cold realm is active, and the airgap guard keeps its policy visible. The shell does not create a shortcut around that boundary.

01

Vault Library

Coldbox can list only vault files or folders you explicitly grant. Select a named vault first; its unlock phrase is entered separately inside the sealed realm. Public names must be unique among vault identities this browser profile or granted library already knows.

No vault files granted yet.

Create a new vault

This name is public and appears in filenames/library. Do not put a passphrase, seed phrase, private key, or other secret here.

02

Save encrypted vault

The prominent Save vault button above writes one canonical .cbx for this Vault ID. File System Access updates that same selected file and verifies it by reading it back. Browsers without writable file handles can download one canonical replacement copy, which remains unverified until reopened.

03

Encrypted text handoff (advanced)

For unusual airgapped workflows, Coldbox can expose the encrypted .cbx bytes as Base64 text. This is not a canonical save and does not count as a verified backup. QR is deliberately not available here.

If clipboard or share access is unavailable, focus the text and use the browser's Copy command. Use a .cbx file for durable storage; use the live animated QR flow below only for device-to-device transfer.

04

Device-to-device vault transfer

Animated QR is a live transfer only. The sending vault must already be unlocked from a durable local .cbx (or have a verified canonical save), nothing can be downloaded from this QR surface, and the receiving device must not already have this vault in its granted library. The receiving device still enters the vault's normal unlock phrase before it can open the transferred copy.

Verify this file

Self-verification is circular, and this says so on purpose. The drop zone below hashes the bytes you give it and compares the result against a value compiled into this same running copy. A modified build could embed a hash that matches its own modified bytes and report a clean match regardless of what was changed. This catches accidental corruption — a bad download, damaged media — not deliberate tampering. For a check an attacker cannot forge, compare against the published .sha256 file with shasum / certutil / Get-FileHash, check the detached GPG signature, and ideally reproduce the build yourself from source. Full instructions: docs/02-security/verification.md in the source repository.
